# studyhelper · 过手总结台

两种界面，一个工具：

| | 干什么 | 一句话 |
| --- | --- | --- |
| **白板**（默认） | 拿笔就画。写公式、写名字、画箭头，**关系靠位置自己出来** | 不用记任何格式 |
| **笔记** | 把整理好的东西收成「量 → 公式 → 关系」的树 | 适合最后通一遍 |

**数据是你硬盘上的纯文本文件，白板文件永远不上传。**
会联网的只有**两个动作，而且都是你点了才发生**：「手写公式」把你写的那一张图发出去
转成 LaTeX；「美化手写」把你**框住的那一块**笔迹发出去认成文字。
两个都不用，就完全不联网，其它一切都在这台机器上。
默认用 DeepSeek 的视觉模型（你已有的 key），认公式也可以切到 SimpleTex。
（密钥只存在本地 `config/ocr.json`，浏览器从来没见过它。详见「手写公式」和「美化手写」。）

> 两个界面是**独立的两套文件**（白板叫 `board-*.md`，笔记叫别的 `*.md`），
> 左边栏的「✎ 白板 / ▤ 笔记」切换。打开软件默认进白板 —— 因为它才是"打开就能用"的那一个。

## 怎么跑

**双击桌面上的 `studyhelper` 快捷方式** → 起服务（**不弹黑窗口**）→ 打开浏览器。

**关掉浏览器标签页，服务自己就停了。** 你不用再"先关服务"。

怎么做到的：页面每 5 秒给服务发一次心跳；正常关标签时页面还会用 `sendBeacon`
当场告别一下，所以**大约 1 秒就收摊**。没来得及告别的（浏览器崩了、被强杀）
最迟 15 秒也会停。两条保险避免误杀：

- **从没收到过心跳的服务永不自动退出** —— 命令行 `curl`、自检脚本、`npm run dev` 都不受影响；
- 按 `F5` 刷新不会误杀：告别之后有 2.5 秒宽限，新页面在这期间报到就作废。

> 想让它常驻别自动退：`node server.js --no-auto-exit`（或设 `STUDYHELPER_AUTO_EXIT=0`）。

### 那个桌面图标是干啥的

它是个**开关，也是兜底**：

| 现在的状态 | 点一下会怎样 |
| --- | --- |
| 没在跑 | 起服务（无黑窗口）→ 打开浏览器 |
| 正跑着 | 停掉服务、释放端口 → 换一张「已停止」提示页 |

平时你根本不用点它第二次——关标签就够了。它是给这几种情况留的：
浏览器崩了/被强杀了导致服务变孤儿、你想马上收摊、或者只是想确认它在不在。

> 也可以不用快捷方式：`启动 studyhelper.bat` 会**在前台**起服务
> （黑窗口看得见，关掉窗口就等于关掉服务）。
> 想改代码看实时刷新：一个终端 `npm run dev`（前端 5180），另一个 `npm start`（后端 5177）。

### 这套启停脚本踩过的坑（改之前先看）

都在 `scripts/` 和 `server.js` 里，全是"看起来能跑、实际不行"的类型：

1. **`.ps1` 必须带 UTF-8 BOM。** PowerShell 5.1 对无 BOM 的 `.ps1` 按本地代码页（GBK）读，
   中文注释被解成乱码、引号被吃掉 → **整个脚本解析失败、什么都不做**，还不一定报错。
   ⚠ 用普通编辑器改完这些文件，BOM 可能会掉，改完就点一次快捷方式验证。
2. **别用 `taskkill /T` 杀服务。** 我们是用「隐藏窗口的 powershell」起 node 的，
   `/T` 会顺着进程树往上爬，把**调用它的那个 shell 也杀掉**（实测：调用方拿到 exit code -1，
   后面的验证代码一行没跑）。现在只杀监听端口那个进程本身，并且把本脚本的祖先 PID
   拉进白名单，命中就跳过。
3. **别在读注册表后不还原"当前位置"。** dot-source 进来的脚本，位置是共享的：读完 `HKLM:`
   不回文件系统，调用方后面的 `Start-Process -FilePath` 会报
   `current provider (Registry) cannot open a file` —— 报错位置和注册表看起来毫无关系。
   现在改用 `Microsoft.Win32.Registry::GetValue`（纯 API），压根不碰位置。
   （`Push-Location`/`Pop-Location` 包起来实测**没用**。）
4. **`$ErrorActionPreference='Stop'` 会把原生命令的 stderr 当致命错误。** vite 会往 stderr
   打一条 "chunk 超过 500 kB" 的提示 → 被升级成终止性错误，表现为
   "构建退出码 0、dist 正常，脚本却报构建失败"。跑原生命令时要临时放成 `Continue`，
   并且只信 `$LASTEXITCODE`。
5. **窗口标题不能要求"精确相等"。** 浏览器会在页面标题后加自己的名字
   （`studyhelper 已停止 - Google Chrome`），所以关提示窗口要用**前缀**匹配。
6. **想自动关掉浏览器标签页？做不到。** 试了 4 轮：`SetForegroundWindow` 成功、前台确认到了
   Chrome、同一手法发 `Ctrl+T` 能开新标签、`Ctrl+Tab` 能切换标签，**但 `Ctrl+W` 就是不动**。
   所以改成导航到一张「已停止」提示页。别再折腾按键关了，这个坑不值得再踩一遍。
7. **自动退出要能测，所以留了两个旋钮**：`STUDYHELPER_AUTO_EXIT_MS`（心跳断多久算断）
   和 `GET /api/state`（把 `lastHeartbeat` / `byeAt` 直接吐出来）。
   没有这两个，这类"什么时候退"的问题只能靠猜——我实测时就因为看不清内部状态，
   一度把自己的测试设计错误误判成功能有 bug。
8. **绝对不要用 PowerShell 的 `Set-Content` / `Add-Content` 改这个仓库里的文本文件。**
   它按本地代码页重编码，**整个文件的中文当场变乱码**。实测连续踩了两次
   （`scripts/check-board.js` 和 `scripts/check-board-browser.js`，都是这仓库的源码）。
   `Out-File` 同理。要改文本就老老实实用编辑器，或者 `node -e` 读写。
   这和上面第 1 条是同一个根因的两个方向：**PowerShell 的默认编码和我们的文件不一致。**
9. **改了 `server.js` / `server-ocr.js` / `src/lib/*.js` 之后，必须重启服务。**
   5177 上跑的是**启动那一刻加载进内存的模块**；`npm run build` + 刷新页面
   只换掉了页面那一半。2026-09-16 就是这么栽的：前端已经是新版（会发
   `mode=text`），服务端还是 30 分钟前启动的旧代码（不认这个字段）——
   于是「美化手写」照样按公式认，**一句报错都没有**，用户报的是
   「美化手写依旧在认公式而不是字」，而我这边所有自检都是绿的
   （那些自检都自己起服务，天然拿到的是新代码）。
   重启：双击桌面开关（关 → 再开），或者 `node server.js --no-open`。
   现在有两道防线兜这件事（见「美化手写」那节的第 6 条），但**改完还是要重启**。

## 白板（默认界面）

打开的是一张**无限大的纸**，一节课一页。手写笔直接画，不用点任何按钮。

**一张板都没有的时候，它会自己给你开一张空的**（`board-新白板.md`）——
因为"打开就是白板"是这个工具的入口，不能因为列表空了就把你丢进笔记界面。
想按课名另建一张，用左栏的「＋ 新建」。

### 画

| 想干什么 | 怎么做 |
| --- | --- |
| 写字 / 写公式 / 画箭头 | 拿笔直接画（默认就是笔） |
| 挪一张卡 | 直接拖它；点一下是选中（右上角出 ×、右下角出缩放柄），**双击**进去改内容 |
| 放大缩小一张卡 | 选中它，拖**右下角那个柄** —— 字和内边距一起变大变小，不是只把框拉大 |
| 取消选中 | 点一下空白，或者按 `Esc`（不选中时卡片上**一个手柄都不显示**） |
| **固定一张卡**（防误触） | 选中它 → 点左下角的 📌（📍 是"没锁"）；锁上之后它拖不动、双击也不会进编辑、也删不掉 —— 想动它就再点一下那颗 📌 |
| 擦掉 | 点「◻ 橡皮」再画，或按 `E`；碰到哪一笔就擦掉**整笔** |
| 做记号 | 点「▬ 荧光」 |
| 框住一块手写（认公式 / 美化 / 整体挪走 / 删掉） | 点「⬚ 框选」再拖一个框，或按住**笔杆侧键**拖（`S`）。框住之后框上方浮出「∑ 公式」「✨ 美化」「✕ 删除」 |
| 平移 | 手指拖 / 中键拖 / 按住空格拖 |
| 缩放 | 两根手指捏；或者滚轮；触控板双指也行 |
| 把所有内容装回屏幕 | `Ctrl` + `0`，或点工具条上的 `⤢` |
| 撤销 / 重做 | `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` |
| **表达两个东西之间的关系** | 直接**画一条线**（画完就成立，不用点任何东西）；想改词就在浮出来的那排里点一下，或者框住那条线再点 —— 见下面「关系：画一条线就够了」 |
| **换纸**（纯白 / 方格 / 横线 / 点阵） | 工具条上「**背景**」那四个小方块，点一下就换 —— 按钮上画的就是那张纸的样子 |

**纸默认是纯白**（原来是一张十字格子纸）。四档都是"浅色纸 + 一层很淡的底纹"，
格线只是给你对齐用的参照，不该跟手写的线抢注意力。
**格线是画在纸上的，不是贴在屏幕上的**：平移、缩放的时候它和你的字、卡片一起动
（格距 = 世界格距 × 缩放），所以字看起来就是写在纸上，而不是浮在背景上面。
选完**当场记住**，下次打开还是它（存在浏览器里，不写进板文件 ——
理由见下面「白板这块踩过的坑」第 18 条）。
「✍ 手写公式」那块写字板跟着换同一张纸 —— 它是"另开的一小块纸"，
板和板长的不是一个样子会很割裂（那块小板本身不跟着视图走，它是独立的一小片）。

**手写笔永远只画画，手指永远只平移缩放。** 这是特意做的：在 Surface 上写字，
手掌蹭到屏幕是常态；如果手指也能画，你每写一行就会多出一条莫名其妙的线。

### 公式：写个大概就行

点工具条上的「**∑ 公式**」放一张公式卡，双击进去写，**按你顺手的样子写**：

| 你这样写 | 它变成 |
| --- | --- |
| `F = ma` | F = ma |
| `dS/dt` | 排成上下分式 |
| `B = mu0 I / (2 pi r)` | 分子 μ₀I、分母 2πr 的分式 |
| `sqrt(x^2 + y^2)` | 根号 |
| `mu0` | μ₀（下标自动出来） |
| `N/A^2` | N/A²（**不**排成分式 —— 这是单位，不是除法） |

卡片下方还有一排按钮（`a/b` `√` `xⁿ` `xₙ` `μ₀` `∫` …），点一下就插到光标处。
**它们插进去的是上面那种写法，不是 LaTeX** —— 面板和手写是同一套语法，
不会出现"面板插的东西我自己看不懂、也没法改"。

两条底线：**认不出来的东西一律原样留着**（宁可丑，不可丢）；
**转化两次等于转化一次**（不然每次重排都可能悄悄改坏内容）。两条都有自检钉着。

> **能不能直接手写公式、自动认出来？** 能，见下面一节。这一条最初是"不做"的
> ——理由是它必须联网，和"不联网、不上传"冲突。后来改了主意：允许联网，
> 但把边界划清楚 —— **只有你点「识别」的那一张图会发出去**，白板文件本身永远不上传。

### 手写公式：写在纸上，它给你排好看

懒得想"该打什么"，就直接写。工具条上的「**✍ 手写公式**」（或按 `W`）打开一块写字板：

1. 拿笔在里面写一个公式（写大一点更准）；
2. 点「识别」；
3. 认出来的式子会**渲染出来**，下面还有一个可以改的输入框；
4. 满意了点「放到白板上」→ 白板上多一张公式卡（卡片上就是那个式子），并且直接进编辑态，随时能再改。

默认走 DeepSeek 的视觉模型（用你已有的 key）；也可以切到专门认公式的 SimpleTex。
配一次密钥就行，见下面。

几个刻意的设计，都是取舍过的：

- **写字板是单独一块，不是"圈住白板上的字去识别"。** 白板上的字是你思考的痕迹，
  位置和大小都有意义；识别后就地替换掉，你会失去"我当初是怎么写的"。
  代价是多一次点击，换来的是白板上的东西永远是你自己放上去的。
- **一次只写一个公式。** 识别服务是"一张图 → 一个 LaTeX"，写两个它会串在一起。
- **认出来先进可编辑框，不直接变卡片。** 识别是帮忙，不是替你做决定。
- **置信度低会明说**（"这次不太准，多半得手动改两笔"）。
- **底部会告诉你"会发一张多大的图"**。发出去的东西你该看得见。
- **认出来的式子在编辑框里，改一下就行。** 识别结果**两个字段都写**：
  显示用的 `tex`、可编辑的 `src` —— 所以"放到白板上"之后编辑框里就是那个式子，看着改，改完回车。
  （只写 `tex` 的话编辑框是空的：式子在编辑态下**看不见**，顺手按个回车还会把它整个抹掉。
  这个坑真踩过，见下面「白板这块踩过的坑」第 10 条。）

#### 已经写在板上的式子：框一圈就行，不用重抄

上面那块写字板是"另开一块地方写"。但更多时候式子**已经在板上了**，重抄一遍纯属浪费：

1. 点「**⬚ 框选**」（或按住笔杆侧键）圈住那个式子；
2. 框上方浮出的按钮里点「**∑ 公式**」；
3. 面板里直接出结果：上面是排好的式子、下面是它的写法（可以改，改坏了会变红、暂时放不上去）；
4. 点「放到白板上」→ 原地落一张公式卡，用的就是你圈的那块地方。

和「✨ 美化」（认普通文字）**共用同一块面板、同一套发图逻辑**，区别只在 `mode`：
一个认式子、一个认字。两条路都要联网、都只发你圈住的那几笔。

> 「∑ 公式」和「✍ 手写公式」不冲突，看你手上是什么：**还没写**就用写字板（写大一点更准），
> **已经写在板上**就框一圈（不用重写）。一次只认一个式子 —— 识别服务是"一张图 → 一个 LaTeX"。

#### 要配一次密钥

默认走 **DeepSeek 的原生多模态模型**（`deepseek-flash`）—— 好处是**用你已经在用的那个
账号和 key**，不用再申请一家。手写公式识别也能用另一家专门的服务，设置里切一下就行。

| 用哪家 | 要什么 | 特点 |
| --- | --- | --- |
| **DeepSeek**（默认） | DeepSeek 的 API Key（`sk-` 开头） | 用你已有的账号；图片发到 api.deepseek.com |
| SimpleTex | SimpleTex 的鉴权串（UAT / APP） | 专门认公式，手写更对路；有每日免费额度（轻量模型每天 2000 次） |

配置步骤（两家一样）：

1. 点「✍ 手写公式」→ 提示里点「去设置」（直接点识别也会自己把设置摊开）；
2. 选一家，把密钥**原样**粘进去；
3. 保存 → 点「测试一下」。

> **模型名会变，所以它是配置项。** DeepSeek 官方已经把
> `deepseek-v4-flash-vision-exp` 标成下线（虽然还能调，但请求由最新的 Flash 承接），
> 现在写的是 `deepseek-flash`。哪天名字再变，在「高级」里改一下即可，不用等改代码。
> 见 [DeepSeek 图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision)。

密钥存在 `config/ocr.json`，这个目录在 `.gitignore` 里 ——
**不会被备份到 GitHub**。换电脑要重新填一次。

#### 想换成自建服务 / 别的服务？

设置面板里有「高级」，改**接口地址**（和模型名）就行。两条路的契约：

**DeepSeek（OpenAI 兼容）**

```
POST {dsBase}                 # 默认 https://api.deepseek.com/chat/completions
Header: Authorization: Bearer <key>
Body:   { model, temperature: 0,
          messages: [ { role: 'user', content: [
            { type: 'text',      text: '<只输出 LaTeX 的指令>' },
            { type: 'image_url', image_url: { url: 'data:image/png;base64,…' } }
          ] } ] }
返回:   { choices: [ { message: { content: "..." } } ] }
```

`content` 必须是**块数组**（写成字符串会被 400）。
模型回的话会被清洗一遍：剥掉 ```latex 围栏、剥掉 `$`、抠出"公式是：xxx"里那句，
回一句中文解释时**当没认出**（绝不把中文塞进卡片）。

**SimpleTex（专门认公式）**

```
POST {base}{|_turbo}          # 默认 https://server.simpletex.net/api/latex_ocr
Header: token: <你那一整串>
Body:   multipart/form-data，字段名固定 file（PNG/JPEG）
返回:   { "status": true, "res": { "latex": "...", "conf": 0.95 }, "request_id": "..." }
```

那一整串是原样发出去的，我们不替你加前缀 —— 鉴权串本身就是"前缀 + 密钥"接在一起的
完整串，替你拼只会拼错。头名字也能在配置里改（`tokenHeader`）。

#### 失败的时候会说人话

原因**分开报**，因为下一步完全不同：

| 界面上的字 | 什么情况 | 该做什么 |
| --- | --- | --- |
| 还没配密钥 | 没填 | 去设置填 |
| 密钥不对 | 401 / 403 | 去设置重填 |
| 额度用完或被限流 | 429 | 等一会儿；余额不足（402）会把对方原话带出来 |
| 连不上识别服务 | 网络 / 超时 | 查网络；写的东西还在，好了再点一次 |
| 没认出内容 | 服务通了但没内容 | 写清楚点、写大点 |

识别是**可选**的：没配密钥、断网、服务挂了，白板和笔记照常用，
只是识别报一句人话。绝不会因为识别失败而丢东西。

### 字丑？框一圈，变成好看的字体（美化手写）

自己的字难看、又不值得打一遍？把工具条切到「**⬚ 框选**」（或按住笔杆侧键），
在板上拖一个框圈住你写的字，框上方会浮出三个按钮：点「**✨ 美化**」——

1. 它把**框里那几笔**渲染成一张图，发给识别服务认成文字
   （走的是"认普通文字"那条路，和认公式不是同一段提示词）；
2. 认出来的字进一个**可编辑的框**，底下有 4 种字体（楷体 / 宋体 / 黑体 / 圆体）
   和一块实时预览；
3. 点「放到白板上」→ 原地落一张**文字卡**，用的就是你挑的字体。

（同一个框上那个「**∑ 公式**」是这条路的双胞胎：认出来的是**式子**而不是字，
落的是公式卡。见上面「已经写在板上的式子」。）

三条取舍，都是有意的：

- **卡片落在你圈的那块笔迹正上方，但不去盖它。** 卡片只按认出来的内容定大小
  （"就让框贴合公式和字"，2026-09-16 定的），所以你的手写会露在它周围 ——
  上一版是"卡片底色不透明、正好把丑字盖住"，代价是卡片的宽高里混进了一份
  "至少要有你圈的那块那么大"，笔迹一被擦掉、或者你只是想让它收一收，
  那份尺寸就变成一片莫名其妙的留白（用户为此报了三轮）。
  **笔迹一个字节都不会少**：把卡片拖开或者删掉，原笔迹原地回来 ——
  这就是"随时能改回手写"，不用为它做任何额外功能（也没有"隐藏墨迹"这种标记要跟着同步）。
- **原笔迹要不要一起擦掉，你说了算**（面板上那个勾，默认不勾）。勾了的话，
  "擦笔迹"和"加卡片"是**同一次操作**：一次 `Ctrl+Z` 把两件一起退回去。
  分成两步的话，你按一次撤销只退了擦除、卡片还留着，看起来像"撤销坏了"。
- **字是"抄"不是"翻译"。** 手写公式那条路会把字排成上下分式；这条路只把字抄下来、
  保住你写的换行，夹在字里的数学符号按普通字符留着。
  要排公式请点同一个框上的「∑ 公式」（或者用「✍ 手写公式」那块写字板）。

**卡片的留白只有内边距那么多。** 内边距是 4/8（原来是 10/12），而且认出来的卡
**宽和高都按真实内容量一次** —— 一行字的卡就是一行字那么高，一行短公式的卡就是那么宽
（原来固定 260 宽，`E = mc²` 居中之后左右全是空的）。文字卡的自然宽度 = 最长那一行，
超过 560 才折行。公式卡里还专门把 KaTeX 给独立公式留的那 1em 上下边距**清零**了：
那是给正文里"上面一段、下面一段"留的呼吸空间，而卡片自己的内边距就是留白 ——
实测那两条边距占了卡片高度的 **52%**（「公式板子周围留白太大」多半就是它）。
**重开一张老板时、以及板子安静下来之后，都会自动量一次**（公式卡）：`w`/`h` 是存在
文件里的旧测量值，只改样式收不掉它，改完内容也一样。
四条量尺的坑都在「白板这块踩过的坑」第 15、16、17 条里。
（**便签卡不自动收** —— 它在关系面板里还有"容器"这个身份：「公式卡整个落在便签里
= 包含」。想让它小一点，拖右下角那个柄。）

字体只用**你系统里已经装了的**（每个预设是一串候选，比如先找霞鹜文楷、没有就退到楷体），
一个字体文件都不下载 —— 为了好看去联网拉字体，就把"不联网"那条底线破了。

**发出去的是框里那几笔渲染成的图**（面板上一直写着"会发一张多大的图"），
白板文件本身永远不上传。用的是「手写公式」那一份密钥设置。
认普通文字**只认 DeepSeek**：SimpleTex 的接口就是"一张图 → 一个 LaTeX"，
配着它点美化，界面会明说"去设置里换成 DeepSeek"，而不是回一堆看不懂的东西。

> 「⬚ 框选」这个工具是专门为这条路加的：原来只有**笔杆侧键**能框选，
> 于是用鼠标的、笔上没有侧键的人根本选不中笔迹 —— 美化对他们完全关着。
> 框住之后浮出的三个按钮是**并列**的：认公式、认文字、删掉。同一块笔迹，
> 你想让它变成什么由你点哪一个决定。

#### 这条路踩过的坑（改之前先看）

1. **`multipart` 的扫描原来"隔一个 part 看一个"。** `/api/ocr` 的请求体里，
   图是第 1 个 part、`mode`（认公式还是认文字）是第 2 个 ——
   而扫描每轮都从"下一个 boundary 之后"接着找，于是**偶数位的 part 永远看不到**：
   `mode` 读出来是 `null`，服务端一直按"公式"处理。表现只是"认不出来"，
   从界面上完全看不出是哪个字段没传。修法是每轮从下一个 boundary 接着扫
   （`pos = next`），并且钉了一条断言：**文本字段排在文件前面时，文件也得找得到。**
2. **浮出来的按钮不能放在屏幕下缘。** 「美化」原来钉在包围框**下面**，
   而底部工具条（z-index 20）横在那一带 —— 自检里 `elementFromPoint` 一眼看出来
   那一点上是工具条，用户按下去只是在戳工具条。现在「✨ 美化 / ✕ 删除」是
   **一条横排、钉在包围框上方**：躲开了工具条，两个按钮也不会互相重叠
   （各自绝对定位时，选框一窄就会叠在一起）。记法还是那一句：
   **浮出来的东西，只有 `elementFromPoint` 能证明它点得到。**
3. **认文字不能复用认公式的清洗规则。** `cleanModelOutput` 里有一条
   "一句话里混着前言 + 公式，就取最后一个冒号后面那段" —— 对公式是对的，
   对笔记是灾难：`安培环路定理：只对稳恒电流成立` 会被砍掉前半句，
   而且**界面上看不出来**（卡片里就是少了一段字，你会以为是自己没写全）。
   所以文字这条路是另一个函数（`cleanTextOutput`）：只剥 ``` 围栏和成对引号，
   **不碰冒号**、多行全留。
4. **`EMPTY` 哨兵那条正则原来只认半角句号。** `这张图里没有文字。` 会漏过去，
   被当成一句正文写进卡片。公式那条漏了没暴露（它的兜底是"有中文就不认"），
   而文字这条的中文**就是正文**、兜底不存在 —— 所以标点得自己认全（`[.。]?`）。
5. **卡片宽度有上限（560 世界像素，一行拉太长没法读）。** 框住一条很宽的笔迹、
   而认出来的字又很长时，卡片会停在 560 宽、把长行折行 —— 不会拉成一条横穿屏幕的长条。
   （2026-09-16 之前这条写的是"卡片盖不满那块笔迹"，因为那时卡片要去盖住笔迹；
   现在卡片只贴合内容，所以"盖不盖得住"不再是问题。）
6. **改了服务端不重启 = "一半新一半旧"，而且完全不报错。**
   2026-09-16 用户报的「美化手写依旧在认公式而不是字」就是这个：
   前端重新构建过（会发 `mode=text`），而 5177 上的 node 是我改代码**之前**启动的，
   它不认 `mode`、照旧按公式认，回一串 LaTeX。界面上没有一句错，看起来就像功能没做对。
   现在有两道防线，都是"当场认出服务端是旧的"：
   - `/api/ocr/status` 里的 `providers[p].modes` —— **老服务端没有这个字段**，
     面板一看就知道，直接提示"关掉再打开一次"；
   - 认文字的**成功回包必须带 `mode:'text'`**，没带一律拒收
     （`lib/ocr.js` 的 `interpretOcrResponse`，纯函数、有断言），
     绝不会把一串 LaTeX 悄悄写进文字卡。
   但根上的规矩没变，见「怎么跑」那节的第 9 条：**改了服务端就重启服务。**

### 卡片和笔：谁让谁

白板上的卡片是"贴在纸上的一张纸"。于是这里有一条分界线，两边都试过才定下来的：

| 你手上是 | 笔尖落在卡片上会怎样 | 为什么 |
| --- | --- | --- |
| **笔** | **写字**（卡片整个让开指针事件） | 笔的语义就是"在纸上写"：卡片上也要能写批注、能圈、能画箭头。墨迹层也在卡片**上面**，所以写上去看得见 |
| **鼠标 / 手指** | **动卡片**（拖动、缩放、双击改内容） | 鼠标没法"写字"，而拖卡片这些事必须一直顺手 |
| 切到「⬚ 框选」 | 卡片对所有设备都可交互 | 用笔的人靠它管理卡片：选中、拖动、缩放、双击改字 |

所以：**笔让路、鼠标优先**。用笔想挪卡片时按一下 `S` 切到框选，动完再按 `P` 切回笔。

几条相关的小规矩：

- **× 和缩放柄只在选中时出现。** 不选中时卡片上干干净净 —— 以前那个 × 会一直挂在右上角等人误点。
- **固定（📌）是第三种状态：这张卡变成"纸的一部分"。**
  锁上之后它整张 `pointer-events: none`，指针事件落到下面的收事件层上 ——
  笔在上面写得出字、鼠标/手指按上去是在纸上（拖不动、选不中、双击也不进编辑）。
  只有角上那颗 📌 自己还收事件（不然就"钉死了拿不下来"）。
  存文件的字段是 `locked`（**不是 pinned** —— `viewPinned` 已经占掉了这个词，
  那个是"视角定住了、下次别自动适配"）。细节见白板踩坑第 19 条。
- **选中就是卡片自己那圈蓝边**（`.bd-card.on`：实线蓝边 + 一圈光晕）。
  > 原来还会在卡片外面**再套一个蓝色虚线框**（`.bd-selbox`）。2026-09-16 删掉了：
  > 它算错了 —— 只乘了画布缩放，**漏了卡片自己的倍率**（卡宽是 `w × 视图缩放 × 卡片倍率`）。
  > 实测那张卡 `scale=4`：卡片 190px 宽，虚线框只有 47.5px，缩在左上角 ——
  > 用户报的「蓝色虚线框不美观，直接删掉吧」就是这个。
  > 记法：**同一个矩形在两处各算一遍，就一定会有一处忘了乘别的东西。**
- **点空白 = 取消选中**（和大多数软件一样），`Esc` 也一样。删错了 `Ctrl+Z` 能回来。
- **缩放柄在右下角，位置固定。** 要是那张卡的右下角正好压在**底部工具条**底下，就会抓不到它
  —— 先把卡片往别处拖一下再缩放。浮层盖住的东西就是点不到的，这条没有例外。
- 用**笔**在卡片上写的时候，笔画不会把卡片拖走、也不会把卡片选中（自检里三条都钉着）。

### 关系：不用你填，是"读"出来的
这是白板和笔记最大的区别：**你没有"关系"这个字段要填。**

点「▤ 便签」放一张便签，把公式卡放到它**旁边**或者**摞在它上面**，
右边「关系」面板就会自己列出谁属于谁。判定顺序（从强到弱）：

| 你怎么摆 | 它算成 |
| --- | --- |
| 公式卡整个落在便签**里面** | **包含** —— "这公式属于这一节" |
| 两张卡搭在一起、差不多大 | **重叠** —— 相关 |
| 两张卡离得不远（26px 以内） | **挨着** —— 手写的人就是这么表达的 |
| 谁都不挨着 | **孤岛** —— 不一定错，可能正是你还没想清楚"它属于哪一节"的地方 |

面板上会写「按位置读出来的」，这是**故意说清楚的**：这是推断，不是你说过的。
想让它变成确定的，就用笔在两张卡之间画一条线 —— 那条线会被认出来（面板里标实线的就是它）。

> **为什么不用"你必须画个框、连根线"那套？** 因为那又变成要你学一套规矩了。
> 位置本身就是关系 —— 这也正是白板比大纲强的地方。

### 关系：画一条线就够了

两样东西之间**画一条线**，就是一条关系 —— 不用选中、不用命名、不用点菜单。

| 你画的样子 | 读成 | 有方向吗 |
| --- | --- | --- |
| 一笔直线 | **相关**（最弱的一档） | 没有 |
| 一笔带箭头的线（末端回勾） | **因果** | 有：你从哪画到哪，箭头就指哪 |
| **一杆 + 一个 V 尖**（分成两笔画，或两撇各一笔） | **因果** | 同上 |
| 画完点浮出来的那排词 | 你点的那个 | 看词 |
| 点那排里的**「不算连接」** | **根本不是关系**（它读错了） | — |

**条件不用你声明 —— 位置说了算。** 写在那条线**中点旁边**的几个字（或者放在那儿的
一张卡），自动成为这条关系的**条件**：面板里那一行会挂上「条件 墨迹块（3 笔）」，
推导链那一节也会把它写进去。你本来就要写"仅当…"，不用再告诉应用这是谁的条件。
四条规矩：只看**中点**周围 64 世界像素；**卡片优先**；这条线自己的笔、以及它**两端的节点**
都不算条件（那是关系本身的两头）；太小的一撮墨不算（2px 的点不是条件）。
**不存盘** —— 位置一变它就变（把那几笔挪走，条件就没了）。

**推导链**：面板里把「推导」那几条串起来读成 `A →(条件) B →(缺条件) C`，
**哪一步没写条件就用橙色标出来** —— 补条件就是"在线旁边把那句话写上"，写完这一节自己更新。

词一共五个：`相关` `因果` `推导` `并列` `等价`（不让自由输入 —— 自由文本第三次
就会变成"我上次写的是哪个词"）。

- **画完就成立。** 屏幕上立刻有标记，不点那排词也什么都有（只是用"形状读出来"的那一档）。
- 那排词是**可选的一步**：画完 3.5 秒内浮在线的上方，不点自己收走。
  以后想改还有一条路 —— **框住那条线**，浮层里会出现同一排词（鼠标用户也能按 `1`~`5`）。
- **认错了要能一键否决**（那排词里最后一个「不算连接」，键盘 `0`）：自动读出来的关系会读错
  （实测：一条 121px 的手写竖笔正好跨过两坨字就被读成连接）。点它 = 这句话记在**那一笔**上
  （`stroke.link = 'none'`），以后不再读成关系；**框住那一笔**还能点「又算回连接」，
  点错了 `Ctrl+Z` 也能退 —— 所有动作都是一步撤销。
- **箭头不用一笔画成。** 一杆一笔、尖一笔（甚至两撇各一笔）都认：杆那一笔本身是直线
  （读成"相关"），但旁边那个尖是它的 —— 合起来就是"因果"。**这也是你实际画箭头的姿势**
  （两张截图量出来的，见下面「白板这块踩过的坑」第 21 条）。
- **尖是你画的，屏幕上就不再叠一个合成箭头。** 有方向的词旁边那个小箭头只在
  "你画的是直线、但手动标了方向"时才画 —— 否则就是一支箭上长两个头。
- **箭头指着的那张卡，离它 34px 之内就算数。** 你画箭头常常**停在卡前面一点**
  （尖得留出画 V 的地方），所以"尖落在卡里"不成立时，看它指着谁。
- 有方向的词旁边画一个小箭头；`⇄` 把方向反过来（渲染出来一模一样，只是箭头换边）。
- 面板里单独一节「**你画过的（N 条）**」—— 连线的两张卡常常离得很远，
  位置推断根本不会把它俩凑一对，但"我画过线"是最确定的一句话，不该因为离得远就消失。

**文件里存了什么**：形状读出来的类型**不存**（直线=相关、带箭头=因果，每次从笔迹重算）；
只有**你手动改过**的那个词写进笔迹的 `link` 字段，而且和自动的一样时**不写**
（选回「相关」= 清掉这个字段）。所以没动过的连接是**零字节**，老文件在 Git 里纹丝不动。

> ⚠ 已知读不出来的手型（都在浮层里点一下就好，不用重画）：
> **尖画得太小**（臂短于 18 世界像素，或者把画布放得很大时画的小箭头 ——
> 判据是世界像素，放大 2 倍时那个尖在世界坐标里就只有一半大）、
> 以及**只画了半个尖**（一笔杆 + 一笔斜线）。
> 想让它认得更准，**把平时画箭头的样子再截一张图发我** —— 阈值按真实手型调，
> 比凭空调参数靠谱（第 21 条就是这么来的）。
>
> 连的是**卡片，也可以是没成卡的字迹 / 手画的图**（2026-09-16 起）：
> 它们在数据层就是 strokes，`buildLinks` 把"端点落在谁身上"从卡片扩成了
> **卡片 ∪ 墨迹块**（笔挨得够近就算一块，现算、不存盘）。见第 22 条。

### 别按 Ctrl+S

**白板是自动存的**（停笔 0.7 秒后写盘）。工具条右下角那个「已存 / 正在存…」就是它。
切文件、关页面之前还会补存一次。

### 数据长什么样

一张板 = 一个文件 `data/board-xxx.md`。**后缀是 `.md`，内容其实是 JSON：**

```json
{
 "title": "大物 · 电磁学",
 "version": 3,
 "viewPinned": false,
 "view": { "s": 0.93, "tx": 70, "ty": 14 },
 "strokes": [ { "tool": "pen", "color": "#1b1d22", "width": 2.6, "points": [106,236,0.5, 201,238,0.5] } ],
 "cards":   [ { "kind": "formula", "x": 100, "y": 190, "w": 320, "h": 100,
                "src": "B = mu0 I / (2 pi r)", "tex": "B = \\frac{\\mu_{0} I}{2 \\pi r}" } ]
}
```

几个刻意的决定：

- **后缀是 `.md`**：现有服务、备份脚本、Git 流程都按 `*.md` 走，改后缀就是改四处；
  而且万一哪天要手改、或者想让别的工具读，"一个开头是 `{` 的 `.md`" 比二进制好救。
  文件名前缀 `board-` 让列表一眼能分开白板和笔记。
- **`points` 是扁平的数字数组**，不是 `[{x,y,p}]`。一个 60 点的笔画，
  对象形式在 JSON 里约 1800 字节，扁平约 400 字节 —— 一节课几百笔，差的是一整个数量级。
  ⚠ 代价是**内存里的形状必须同一个**：解析时一律收敛成扁平数组（见下面坑 #1）。
- **坐标是世界坐标**，缩放平移**不改数据**，只改 `view`。换个缩放再打开，画的东西还在原地。
- **存之前会抽稀**（道格拉斯—普克，容差 0.6 像素）。不抽稀的话，
  Surface 的笔一秒能报 240 个点，一节课的文件能到几兆。
- **`viewPinned` 是个小开关**：`false` = 打开时自动把所有内容装进屏幕；
  `true`（你亲手平移/缩放过）= 老实按存下来的来。为什么需要它 ——
  `tx/ty` 是**相对画布容器**的坐标，容器一变（换摆法、改界面字号、改窗口大小），
  旧坐标就是个错的位置。与其猜"要不要迁移"，不如只在你真的动过之后才记住。
- **文字卡的 `font` 只在它不是默认字体时才写进文件。** 无脑写出去的话，
  你打开软件、一个字都没改，所有老板文件在 Git 里全部变成"已修改" ——
  那正是"每天一条假 diff、然后你学会忽略 diff"的开端（和上面压力保留两位小数同一个道理）。
- **连线的 `link` 同理，而且更严**：只有你**手动点过**那个词才写，而且和
  "形状自动读出来的"一样时**不写**。所以"画了一堆线但一个词没点过"的板，文件里一个字节都不多。
  读盘时认不出的字体名一律退回默认，所以手改文件也改不坏。
- **卡片的 `scale`（放大缩小倍率）也只在不是 1 的时候才写。** 理由和上一条一样。
  它和 `w`/`h` 是两件事：`w`/`h` 是**布局尺寸**（决定文字在哪里折行），
  `scale` 是倍率 —— 字号、内边距、圆角、宽高**一起**乘它。
  拖右下角改的是 `scale`：只把 `w`/`h` 改大的话，卡片会越拉越大、字还是那么小，看着像坏了。

### 白板这块踩过的坑（改之前先看这段）

全是**静默**类型的错：不报错、不崩、状态栏数字看着也对，就是屏幕上不对。

1. **内存里的点必须是扁平数组。** `parseBoardDocument` 一度把点规范化成对象数组，
   而画布按扁平数组读下标 `0/1/2` —— **一笔 10 个点被读成 3 个**，画出来长度是 0，
   屏幕上一片空白；但文件内容、笔数、状态栏全都正常，查了很久都像渲染的问题。
   现在 `normalizeStroke` 一律 `toFlat`，`drawStroke` 走 `toPoints`（两种都认）兜底。
2. **`Array.from(arr, fn)` 会把 `(元素, 下标)` 一起传给 `fn`。** 写序列化的时候
   别图省事把 `round(n, digits)` 直接当 mapFn 传进去 —— 下标会被当成"保留几位小数"。
   包一层箭头函数。
3. **`tx/ty` 和卡片定位必须是同一个基准。** 这一条栽了**三次**：
   canvas 的 `ctx.setTransform` 画在 `.bd-stage` 坐标系里，而一个绝对定位 div 的
   `translate(tx,ty)` 是相对**它自己的包含块**算的。两者一旦不同源，
   卡片就整体偏一个"侧栏宽 + 顶上那一行高"（实测 270 / 46 像素），
   表现是"手写的线和公式卡对不上、内容跑到屏幕外看不见"。
   现在：**任何 `clientX/clientY` 进 `Board.jsx`，第一件事就是减掉容器的 rect**；
   卡片位置也改成用 JS 按同一个公式算 `left/top/width`，不再用 CSS transform 表达视角。
4. **白板那一块必须包一层再放进网格。** `.app` 是 grid，把三列改成两列时，
   只给画布元素指定 `grid-column: 2 / grid-row: 1` 是不够的 ——
   它的兄弟元素（顶上那行文件名）会被**自动放进第 2 行**，
   于是第一行只剩画布、第二行被文件名占掉，看起来就是"白板高度莫名少了一半"。
   规则要写在外层容器（`.bd-shell`）上。
5. **"打开时全部装进屏幕"必须有缩放下限。** 实测在 758×426 的窗口里会算出 0.37 倍，
   公式小到看不清。现在有 `READABLE_FIT_S = 0.55`：
   宁可让你平移着看，也不能把板缩成蚂蚁。
6. **改完模块，页面不一定是新的。** 开发服务器（vite）的 HMR 只换它认得的那一块；
   改的是被 `import` 的数据模块时父模块未必重建 —— 你会看到"明明改了代码，页面还是老样子"。
   实测被骗过一次：样板从 4 张卡加到 5 张，页面一直是 4 张。
   `node scripts/cdp-reload.js` 强制重新导航。
   **另外：5177 端口跑的是 `dist/`（构建产物），不是源码** —— 改完必须 `npm run build`。
7. **`setPointerCapture` 要设在"收到事件的那个元素自己"身上。**
   写字板第一版把捕获设在了外层的 `.wp-padwrap` 上，而监听器挂在 canvas 上 ——
   于是 `pointermove` / `pointerup` 全被重定向到那个 div，
   结果是"笔迹画出来了（实时重画生效），但一笔都没记下来"：
   界面永远停在「还没有笔迹」，点识别只会弹一句"先写一个公式"，
   而且**一个报错都没有**。表现和"画布坏了"一模一样，特别容易查错方向。
8. **别用 `fetch` 连本机 HTTPS。** 实测 node 内置 fetch（undici 实现）连本机 HTTPS
   **会挂住不返回**，而同一个地址用 `tls.connect` / `https.request` 一秒就通。
   所以这个项目所有出网请求都走 `src/lib/http.js`（用 `node:http/https` 手写），
   multipart 也是自己拼的（`src/lib/multipart.js`）。
   `scripts/diag-net.js` 把这条结论钉住了 —— 谁想把 `http.js` 换回 fetch，先跑它。
9. **"打开哪一个"决定了进哪个模式，所以"一张板都没有"必须也进白板。**
   `App.jsx` 打开时挑**列表里第一个 `board-*.md`**：挑到就进白板，挑不到就打开第一个笔记。
   上一版只在"`data/` 完全为空"时才补样板板，于是**把板删干净、笔记还在**的时候，
   打开就是笔记界面 —— 想画还得先点「白板」、再回答一个"这一课叫什么"的弹窗
   （2026-09-15 用户报的就是这个）。现在 `ensureBoard()` 兜底：一张板都没有就补一张**空**板
   （不是样板 —— 用户把板删干净了，说明他要自己来），名字 `board-新白板.md`，
   撞名往后排 `board-新白板 2.md`（服务端 `/api/new` 撞名回 409，不先探一遍就是静默失败）。
   **连带的两件事**：
   - 笔记界面的自检（`cdp-align` / `cdp-caretfit`）不能再靠"环境里碰巧没有板"活着了 ——
     现在会进白板，报出来是「找不到 textarea 或 .hl-inner」这种假错。改法见
     `scripts/lib/note-mode.js`：**自己点左栏「笔记」切过去**，和 `check-board-browser`
     自己造夹具是同一个道理：自检要自己保证处在需要的环境里。
   - 夹具板也不再有"排第一"的特权（`board-新白板.md` 按字典序压在 `board-zz-check.md` 前面）——
     `check-board-browser.js` 现在写完夹具后**点左栏那一行**打开它，不依赖排序。
10. **手写识别插进来的卡片，必须把式子同时写进 `src`。**
    `insertRecognized` 原来是 `src: ''` + 只写 `tex`，而**编辑态编辑的是 `src`、
    编辑态又只渲染那个输入框**（不渲染 tex 的公式）。后果：
    "放到白板上"之后卡片里只有一个**空框**，刚认出来的式子一个字都看不见；
    用户顺手按个回车，`commitEdit` 就把 `tex: toTex('')` 写进去，整张卡变成"双击写公式"。
    实测（2026-09-15，真浏览器 + 假识别服务）：插入后编辑框 `value === ""`，
    按一次回车 → 文件里 `tex`/`src` 全空。
    用户报的正是这个：「识别是对的，但放不到白板上，还弹出一个没法交互的弹窗」
    —— 那个"弹窗"就是卡片里的空输入框。
   现在：插入时 `src: tex` 一起写；并且 `commitEdit` 里**空提交什么都不改**
   （想清空有「删除」，想放弃有「取消」）。`npm run check:ocr-browser` 的 [5] 盯着这两条。
   **连带的老文件地雷**：这个 bug 出之前写下的公式卡（早期版本故意留空 `src`）自己在盘上躺着，
   只改 `insertRecognized` 救不了它们。所以 `src/lib/board.js` 的 `normalizeCard` 在**读盘时**
   就地补：公式卡有 `tex`、`src` 为空 → `src = tex`。手打过的 `src` 一个字不动，
   便签卡不会被塞进 `tex`（这三条在 `check-board.js` 的 [6] 里各有一条断言）。
   在解析层修，所以老文件是"自己好"，不用手改 `data/`。
   **⚠ 但用户那句里的「没法交互」不是这一条，是下面第 11 条** ——
   第 10 条只解释了"框里为什么看不见东西"，"半点都点不进去"另有原因。
11. **卡片必须待在比收事件层（`.bd-hit`）更高的那一层，否则整块白板"点不了"。**    2026-09-15 用户第二次报同一处，挖到的才是底：卡片（`.bd-card`）自己是
    `position: absolute` + `z-index: auto`，而 `.bd-hit` 是 `z-index: 5`。
    按 CSS 的绘制顺序，**正 z-index 的定位元素排在所有 `z-index: auto` 的定位元素之后
    （也就是更上面）** —— 于是 `.bd-hit` 把卡片整个盖住。症状三条一起来：
    · 点卡片 = 在板上落一笔（而墨迹层也在卡片上面，笔画就落在卡片脸上）；
    · 卡片选不中、拖不动、双击进不去编辑态；
    · 卡片里那个输入框一个字都点不进去。
    用户的原话：「点不了，给我识别成写字了，然后我在弹窗上乱涂乱画无法交互」。
    **自检为什么一直绿灯**：`check-board-browser` 原来是
    `card.dispatchEvent(new MouseEvent('dblclick', { bubbles: true }))` ——
    合成事件**直接投给卡片这个元素**，绕过浏览器的命中测试，
    所以"卡片点得到"这条从来没被验过（它还顺带掩盖了墨迹画在卡片上面）。
    现在：`BoardCanvas` 把卡片包进 `.bd-world`（`z-index: 6`，只负责叠放，
    **绝不给它加 transform** —— 坐标是卡片自己算的，加变换就等于平移两次，见第 3 条）；
    两条浏览器自检都改成 `Input.dispatchMouseEvent` 真鼠标，
    并且先用 `elementFromPoint` 看一眼"这一点上最上面的是谁"。
    记法：**沾指针的东西，只有真鼠标事件能证明它点得到；
    `dispatchEvent` 只能证明"处理器写得对"，证明不了"用户按得到"。**
    连带改的是自检里"画一笔"的落点：卡片现在真的收指针事件了，
    落点踩在卡片上那一下是**拖卡片**，不是画线（设计就是"卡片能选中、空白能画"）。
    所以 `check-board-browser.js` 里加了 `findEmptyRun` / `emptyXOnRow`：
    用 `elementFromPoint` 找真的空白，而不是"估个坐标，差不多是空地"。
12. **墨迹原来画在卡片下面，所以"在卡片上写字"写了也看不见。**
    用户 2026-09-16 报的四条（不能移动 / 不能放大缩小 / 一直挂着 `×` / 无法在卡片上写字），
    最后那条的根子有**两半**，缺一半都不成立：
    ① 卡片收指针事件，笔尖落上去是在**拖卡片**，一笔都不落；
    ② 就算落到板上，墨迹层（原来的 z-index 1 / 3）也在卡片（6）**下面** —— 写了看不见。
    现在墨迹两层提到卡片之上（8 / 9），并且**用笔时卡片整个让开指针事件**
    （`.bd.penink .bd-card { pointer-events: none }`，由"上一次是什么设备"决定）——
    规则和理由见「卡片和笔：谁让谁」。
    ⚠ 这一条和第 11 条只差一点，别混：第 11 条说的是**收事件层**（`.bd-hit`）盖住卡片，
      那是"点不到"；这条说的是**墨迹和卡片的绘制顺序**，那是"看得见看不见"。
      两件都跟 z-index 有关，一个是命中、一个是绘制。
    **自检怎么钉的**：用真笔事件（CDP 的 `pointerType: 'pen'`）在卡片中心画一笔，
    然后**截一张图、拿回页面里解码、读那一点的像素** —— 读到墨色才算过。
    只断言 z-index 是假安心（z-index 高 ≠ 画得出来、看得见）。
13. **拖拽手柄不能只靠自己身上的 `onPointerMove`。** 缩放柄只有 18px，
    鼠标拖两下就出去了，后续事件全落到别处 —— 表现就是"拖了没反应"
    （实测：拖了 120px，倍率纹丝不动，而代码看着完全正确）。
    现在这个手势的 move / up **挂在 `window` 上（捕获阶段）**：不管指针跑到哪都算数，
    也不怕被卡片的 `stopPropagation` 吃掉。
    同族的一个坑：**浮出来的东西不能放在屏幕下缘** —— 缩放柄和之前那个「✨ 美化」按钮
    都被底部工具条（z-index 20）盖过，两次都是 `elementFromPoint` 一眼看出来的。
    现在自检里有两条兜着：**"缩放柄中心命中的就是它自己"**，以及
    **"页面上不许有任何 JS 报错"**（处理器抛异常和处理器没跑，在屏幕上是同一个样子）。
14. **`×` 一直挂在卡片右上角，是因为插入之后那张卡一直"选中着"。**
    原来点空白只清 `inkSel`、**没清 `selectedId`** —— 于是刚放上去那张卡永远带着 `×`，
    在那儿等着被误点。现在点空白 / 按 `Esc` 都会取消选中，
    **不选中时一个手柄都不显示**。记法：选中状态只在"你正在动它"的时候才该亮着，
    常驻的删除按钮就是个陷阱。
15. **卡片底下的空白 = min-height 和内容对不上；"量内容"这件事有三个坑，第三个最阴。**
    用户 2026-09-16 报了两轮：「无论是公式还是字体卡片，边缘留白都太多了」，
    第二轮回来说「识别公式留白依旧很多」—— 因为第一轮我只治了**高度**那一轴。
    账是这么算的：内边距 10/12 → 4/8；新卡默认高 96 → 44（一行字只有 30 出头）；
    认出来的卡**宽高都按真实内容量一次**（`fitCardSize`）。
    宽度那一轴尤其要紧：公式卡原来固定 260 宽，一行短公式居中之后左右全是空的。
    下面三个坑，一个比一个难查：
    · **只能量内容（`.bd-card-body`），不能量卡片自己** —— 卡片的 `min-height` 就是 `h`，
      量它等于量自己，96 的卡量出来永远还是 96，空白永远消不掉。
      内容高度只跟宽度和字号有关，所以量完写回去不会来回振荡（振荡＝每存盘一条假 diff）。
    · **编辑态量不得。** 那时候卡片里装的是编辑器（输入框 + KaTeX 预览 + 一排符号按钮），
      实测把 `h` 写成了 **204**，是真正内容的好几倍。现在改成"挂起来，等退出编辑再量"
      （`pendingFitRef` + `editingId` 一变就跑）。
    · **⭐⭐ 算尺寸必须加上内边距和边框。** 这个仓库全局是 `box-sizing: border-box`，
      卡片上写的 `width` **把内边距和边框算在里面**，内容实际拿到的是 `width − 这一圈`。
      忘了加，内容就被**当场裁掉**：实测 `E = mc²` 的 `c²` 直接不见
      （正好少 18px = 8+8 内边距 + 1+1 边框），而卡片尺寸、我的两条断言、控制台
      **全都是正常的** —— 因为"卡宽 − 内容自然宽"两边都错在同一个数上，
      比出来正好是 0，绿得理直气壮。
      后来加上去的硬判据是**内容有没有溢出**（`tex.scrollWidth > tex.clientWidth`）：
      它不看两边是否"一致地错"，只看内容是不是真的被裁了。
      教训：**"两个数一样"不等于"两个数是对的"**；
      能证明"结果可用"的断言，比证明"过程自洽"的断言值钱。
    ⚠ 两条相关的取舍：
      · **两张卡都量宽度**（`fitWidth`）：公式是一行不折行的，自己多宽就是多宽；
        文字卡的自然宽度 = **最长那一行**（识别结果保住了你写的换行，所以不会变成一长条），
        超过 `TEXT_CARD_MAX_W`（560）才折行。
      · **便签卡不做"板子一静就自动收"**：`h` 在这个应用里还有第二个身份 ——
        "容器"的尺寸，样板板靠一个 520×420 的便签**装住**两张公式卡来演示「包含」。
        实测（2026-09-16）连便签一起自动收之后，`check-board-browser` 那条
        "连线 ≥3（2 包含 + 1 挨着）"当场变成 0 条 —— 关系推理整块塌掉。
        刚认出来的文字卡照样贴合内容（那一刻由插入路径排一次量尺寸），
        要更紧凑的便签就拖右下角那个柄。见第 16 条。
16. **只治渲染不够：`w`/`h` 是存在文件里的旧测量值，卡片必须自己重新量。**
    2026-09-16 用户报了三轮留白，每轮挖出来的东西都不一样，合起来才是全貌：
    · 第一轮「无论是公式还是字体卡片，边缘留白都太多了」→ 内边距 10/12 → 4/8（第 15 条）。
    · 第二轮「识别公式留白依旧很多」→ 宽度那一轴：公式卡固定 260 宽（第 15 条）。
    · 第三轮「公式板子周围留白太大」+「依旧神秘留白出现，这框不贴合公式」→
      **三个**来源，缺一个都治不干净：
      · **KaTeX 的 display 边距**（`margin: 1em 0`，那是给正文里独立公式留的呼吸空间）。
        那张卡字号 50.25px，两条边距 = 100.5px，而卡片总共才 191.8px 高 ——
        **52% 是空白**。修法在 `styles.css`：`.bd-tex .katex-display { margin: 0 }`

17. **"提交完立刻再量"量到的是上一次渲染的世界 —— 卡片会钉在一个错的高度上，而且不会自愈。**
    2026-09-16 抓到的（靠把每一趟都记在 `window.__fitLog` 上才看明白）：
    `scheduleFits()` 有几处调用点，两个 rAF 会落在**同一帧**里，于是
    `runPendingFits` 连着跑两趟 —— 第一趟提交了新的宽度（文字卡 w 220 → 299），
    第二趟在**同一毫秒**又量了一次，而 DOM 还没重渲染（量到的还是 220 宽）：
    它看到的仍是"折成三行"的内容，于是把高度钉在 94.4（正确值 66），
    又因为宽度那一趟已经相等了 → 判成"稳定" → 收工。屏幕上就是"卡片比字高出一行"，
    重开文件也不会好（存下去的就是 94.4）。
    两条修法，都在量尺寸那一族里（现在住在 `src/lib/card-fit.js` 的 `fitPass`）：
    · **量之前先确认 DOM 的宽度已经等于数据里的宽度**（`cur.w * s * scale`）——
      对不上就返回 `'stale'`，下一帧再来。写完就提交、提交完不能立刻再量。
    · **稳定性要两条轴都稳**（`needH` + `need`）：只比宽度的话，
      "宽度不变、高度还在收敛"那一趟会被误判成收敛。
    记法：**提交完不能立刻再量 —— 你量的是上一次渲染的世界。**
    （同族的坑还有一条：这里量的都是**布局**尺寸，而布局是按帧更新的；
    所以"量完写回去、再量一遍"这件事必须发生在**下一帧**，不能在同一个调用栈里连做两遍。）
    ★ 2026-09-16（N2）之后这两条在 `check-board.js` 的 [6l] 里**断言得住**了：
    假 sample 把 DOM 固定成"永远报旧的 220 宽"，连跑三趟 —— 必须只提交一次。

        基准要取"这一头**往外**的方向"（`endOutward`）。

        尾巴挑到臂那一头，那张卡不在尾巴上，于是"画了箭头却没有连接"，屏幕上一点异常都没有。
      · **接笔（`joinStrokes`）比看上去危险得多。** 一条连接分两笔画要接起来，但：
        只接"**一笔的末 → 另一笔的首**"（首↔首 是"从同一点拉出去的两根线"，接了会把其中一条吞掉）；
        还要**顺着往下**（夹角 ≥ 150°，不然 A→B、B→C 会被接成 A→C）；
        **接头落在卡片里就不接**（那是连接的端点，两根线各自画进同一张卡就是这个样子）。
        三条都是被 `check-board` 的老断言当场抓出来的。
      · **"两端各落在一张卡里"永远优先于"形状"**，而且 `a/b` 顺序**按你画的方向**
        （⇄ 的实现就是"把这一笔的点倒过来"，倒了 a/b 不换 = ⇄ 坏了）。
        顺序反了的代价：一个 V 形连接（从上方的卡画下去、再进另一张卡）会被当成"箭头尖"，
        整条连接凭空消失 —— check-board [5] 抓到的。
    **怎么拿真实笔迹当夹具**（这套以后还会用）：
      · `scripts/extract-hand-arrows.py` → `scripts/fixtures/hand-arrows.json`
        （中心线点列，**出关格式就是应用自己的扁平三元组**，自检里不用再转一道）
      · `check-board.js` 的 **[6e]**（纯逻辑，两种箭头 × 五种画法）+
        `check-link.js` 的 **[6b]**（真浏览器：把那两条点列**按屏幕映射画一遍**再断言）
      · ⚠ 骨架那一步踩了两次：Zhang-Suen 的两个删除条件写成了"与"（应该是"三者的与非"），
        细化等于没做；8 连通的斜线上会天然长出度数 3 的"台阶"像素，
        所以"分叉点"要先并成**簇**再算 —— 更省事的做法是干脆不找分叉点：
        取"骨架直径"当主干、剩下那坨当附属臂（`dissect`）。
      · ⚠ 别拿夹具里写的卡片世界坐标反推屏幕位置：**打开板子时应用会按内容重算卡片尺寸**
        （第 16 条），`w:220` 到屏幕上就不是 220 —— 拿它算会整体偏上百像素。
        自检改成"按**量到的**卡片屏幕位置摆，再用应用存下来的点映回来对一次"。

22. **"连接的可能是没成卡的字迹、我画的图"—— 那就要把"端点落在谁身上"从卡片扩成"墨迹块"。**
    2026-09-16 用户补的约束：「连接的不只是卡片，可能还有我没转化成卡片的字迹，
    我自己手绘的图」。做法：`buildLinks` 里那个 `cardAt()` 换成 `nodeAt()` ——
    **卡片 ∪ 墨迹块**，块 = 笔与笔挨得够近（≤ `INK_BLOCK_GAP` 24px）的连通分量，
    **现算、不存盘**（`groups` 字段还空着，留给以后的"框选固化"）。
    一块的 id 取块里最小的那个笔迹 id，所以只要成员不变它就稳定。
    **三道闸**（阈值全是拿他板上 439 笔量的，不拍脑袋）：
    · **够长**：≥ `INK_LINK_MIN_LEN`(48px)。实测他笔画长度中位 **26px**、99% 不到 146px。
    · **中段是空白**：弧长 30%~70% 那五点，离别的墨都要 ≥ `INK_LINK_MID_GAP`(18px)。
      这条挡"长横线"：公式的分数线中段上下就是分子分母，一量就贴着。
    · **两头各落在不同的节点里**：字里的一横两头在同一坨里 → 直接出局。
    ⚠ 两个坑，各踩了一次：
      · **连接线的两头是扎在字迹里的** —— 先聚块再判线的话，那根线会把两块粘成一块，
        "两头不同节点"永远不成立，**一条都出不来**。顺序必须是：
        先挑出够格当线的笔 → 再排除它们 → 才聚块。
      · **中段采样要沿折线插值**，不能"取离目标弧长最近的那个现有点"：
        一条直线笔迹可能只有两个点（存盘前会抽稀），那样 30% 和 70% 都落在两个端点上，
        而端点正扎在字迹里 → 中段判据永远不通过（[6f] 就是这么抓出来的）。
    · **卡片优先于块**：一支箭头指着卡片时，尖旁边那两撇墨不能被当成目标
      （[6e] 的两笔箭头当场被抢走过）；解"尖指着谁"时还要**把自己画的尖排除掉**。
    · 已知代价（钉在 [6f] ⑦）：两块挨得近、线又画得短时认不出来（中段采样点落进端点墨里）。
      **把线画长一点**（跨过空白）就认了。中段阈值从 18 降到 12 能让它认出来，
      但实测**真板上会多一条假连接**（一条 121px 的手写竖笔被读成"卡→字迹"）—— 所以是 18。
    · 卡片↔卡片那条路**一条闸都没加**（它铁定是连接），[6f] ⑥ 钉着"卡间短线照样连"。
    · 性能：这是每次 commit 都要跑的，所以索引只建一次（`createInkIndex`，
      按 `board.strokes` 缓存，拖卡片不重建）、块只 flood fill 一次（`index.owner` 记忆）、
      格子键用**数字**不用字符串。当前 620 笔的板上 `buildLinks` ≈ 30ms
      （改之前 ~23ms + 另一份重复的 `buildLinks` ~17ms；顺手把那份重复删了，净账反而更低）。
    · 自检：`check:board` 的 **[6f]**（20 项：两块之间画线 / 分数线 / 中段压墨 / 卡→块 /
      真手画箭头指着字迹 / 同一块内部 / 短线的代价 / 块的 id 稳定性）。
    · **自动判定必须配一个否决权**（同一天做的第二件）：形状和位置都会读错，而在那之前
      认错了只能**擦掉那一笔重画** —— 那就是"猜错还锁死"，这套设计最怕的事。
      做法：那排词最后加一个「**不算连接**」（键盘 `0`），存成 `stroke.link = 'none'`
      （不是往 `LINK_KINDS` 里加第六个词 —— 那排词回答的是"是什么关系"，这个回答的是
      "它根本不是关系"）；`buildLinks` 见到这个值整条跳过，`normalizeStroke` /
      serialize 都原样保留它（丢了它，下次打开那条假连接就自己回来了）。
      ⚠ **否决本身也必须有回头路**：一句话说出口、重开之后就没路了，那还是单向门。
      所以框住那一笔时浮层里会多一个「又算回连接」（清掉那个字段、回到按形状自动判），
      而且它是**一步正常的撤销**（`Ctrl+Z` 也回得来）。
      · 自检：[6g]（7 项：本来是连接 → 标 none 就不再是 → 标 cause 仍然是 → 存盘/读回 →
        没标过的板一个字节都不多）+ `check:link` 的 [9]（真浏览器走一遍：画线 → 点否决 →
        存盘 → 重开还在 → 框住 → 点回来 → 文件里那个字段也去掉）。
    · **自动聚类聚错了，你得有地方纠正它**：框住一块 → 浮层上「**⧉ 固定成一块**」
      （写进 `groups`，只在真有固定块时才写这个字段）；两块各自固定 = 把它们**拆开**；
      框住正好一整块时那颗按钮变成「**⧉ 拆开这块**」。固定块的 id 是 `grp:<组 id>`，
      跨重开一样；成员被擦光的组**自己消失**，删掉一笔时那个死 id 也不再写出去
      （文件里不留尸体）。自检：[6h] 13 项 + `check:link` 的 [10]（真浏览器：
      框选 → 固定 → 文件里有 → 按钮翻面 → 拆开 → 字段没了）。

23. **"在你现在这张板上量不出假连接" ≠ "干净"——要用更脏的那份板当对手。**
    2026-09-16 的第三轮做完"墨迹块"后，拿当时的板（439 笔）量是 0 条假连接，我就以为稳了。
    后来拿 `.cache/board-baseline.md`（**620 笔**，因为少笔那件事留下来的快照）量，
    立刻冒出一条：**一张公式卡 → 一个 2px 的小点**，读成"因果箭头"。
    一条一条查下来，是三个真 bug，全都跟"自动"有关：
    · **箭头指的"东西"可能小得没有意义**。他手写公式里有个 2px 的点，旁边一条 121px 的
      竖笔 + 一个 V 形短笔，于是被判成"从卡指向那个点的箭头"。→ 加 `INK_NODE_MIN_SIZE`
      （包围盒对角线 18px）：比这小的不算"一个东西"。（你**亲手固定过**的块不走这条。）
    · **缓存不能跨排除集共用**。"尖指着谁"那一次查询要把**箭头自己的尖**排除掉，
      而它算出来的节点被写进了通用缓存 —— 下一次别的查询读到它，
      目标就变成"箭头那两撇 + 一个小点"（`bLabel` 写着"墨迹块（2 笔）"，那 2 笔就是它自己）。
      → 缓存**按排除集分开**（`cacheKey`），不是关掉缓存（关掉会让 620 笔的板上
      `buildLinks` 从 26ms 涨到 450ms，实测）。
    · **有尖的链不许再走"两头落在谁身上"那条兜底**。尖端正贴着他自己画的尖，
      那条兜底一跑就把箭尖当成了目标。→ 那条路**只在没尖的时候**走。
    记法：**自动判定的 bug 只会出现在"内容更密、更杂"的输入上** ——
    自己造的夹具（几坨干净的字）永远试不出来。`board-baseline.md` 现在被当成了
    这一族的对手盘：动连接/墨迹块的代码，除了跑自检，**还要拿它量一遍"凭空多出几条"**。

24. **自检里"按屏幕像素摆/画"之前，先把视图缩放量出来。**
    2026-09-16 做"条件从位置送"（第 22 条那条线的第三步）时踩的：
    要验"在线**中点旁边**写几个字 → 它成为条件"，就得真的在浏览器里画那两笔。
    我按屏幕像素画了 22px —— 而条件有两条闸（块的个头 ≥ 18 **世界**像素、
    中点在 64 **世界**像素之内），fixture 的视图一缩放，22 屏幕像素只剩十几世界像素 →
    "个头不够"，条件读不出来。**报出来是"条件没被读出来"，看着像功能坏了。**
    修法：缩放从**两个已知点**量 —— 夹具里那两张卡的**屏幕距离 ÷ 世界距离**
    （`wDist` / `sDist`），然后用它把"我要摆多少世界像素"换算成屏幕像素。
    记法：**自检里凡是"位置/尺寸"的断言，都要说清是世界还是屏幕**；
    跨这一层的地方（画布、卡片、笔迹）**一律有缩放**，按屏幕像素写死就是等它以后翻脸。
    （同一个坑的另一面：`check-ocr-browser` 从"左上角 +8/+4"拖卡片 —— 那也是屏幕像素。）

25. **"自检全绿"和"功能真能用"是两件事：自检要**走应用的真实路径**，不能只直接调那个函数。**
    2026-09-16 让一个独立 agent 挑刺 + 自己写对抗性探针（随机板 + 不变量 + 新旧版本对照），
    一共挖出 **7 个真 bug**，其中一个正好把上一轮的功能整个废掉：
    · **【严重】固定块（`groups`）在 `buildLinks` 里完全失效。** `createInkIndex` 把固定块登记在
      `owner` 上，而 `owner` 在 `dropKey` 变化时被清掉 —— `dropKey` 初始是 `undefined`，
      所以**第一次 `buildLinks` 就把它清光**。表现：固定之后①本来连得上的连接**消失**、
      ②把相隔很远的两坨固定成一块，反而**凭空造出一条连接**、③块的名字/成员退化成临时节点。
      **自检为什么没抓住**：`check-board [6h]` 是直接 `inkNodeAt(createInkIndex(...))` 问的，
      没走 `buildLinks`；`check:link [10]` 只验了"文件里写了没有 + 按钮翻面"。
      → 修法：固定块单独放 `index.fixed`（不被缓存清理碰到）；**补的断言必须走 `buildLinks`**。
    · **【中】缓存跨排除集串味**：带额外排除集的查询（"尖指着谁"、"线中点旁边是什么"）
      和普通查询问出来的**不是同一个块**，共用一个缓存就会互相读到对方的答案
      （表现：条件里混进这条线自己、同一块拿到两个 id）。修法：按排除集分缓存，
      而且"忘了给 key"要**降级成不缓存**（正确优先），不能降级成串味。
    · **【中】别的连接线被当成"条件"**：条件要排除**所有成为连接的链**的笔，
      而"哪些链成了连接"得等端点都解完才知道 → 条件必须放**第二趟**算。
    · **【中低】条件卡只在"最近一张卡"里找**：最近那张要是端点卡就整体放弃卡片分支，
      于是真正写在中点旁边那张卡被漏掉 → 半径内按距离试、跳过两端的卡。
    · **【中低】推导链在分叉处丢分支**（A→B、B→C、B→D 只显示前两条）：改成每条路都走，
      超过上限要**标记 truncated**（不能静默截断）。
    · **【中低】界面能写出"一笔属于两个组"**（先固定 {s1,s2} 再固定 {s2,s3}）→
      读回来被静默改掉。修法：`freezeGroup` 先把这些笔从别的组拿走；serialize 也去重一道。
    · **【低】「又算回连接」只清选中的笔**（而 `link:'none'` 写在整条链上）→ 点了没反应。
    · **【低】"点线即选中"的小框判据用世界像素、命中半径用屏幕像素** → 放大后轻拖就变成"点"。
    ⚠ 顺带挖出一个**更早的老 bug**（第 4 轮就写进去了）：`joinStrokes` 的"角度闸"判的是
    **偏转角**，却拿"顺着往下 ≥150°"的阈值去卡 —— 等于**只接折回来的笔**，
    恰恰不接"分两笔画、方向接着往下"的那种（实测：直线续画 → 2 条，折回来 → 1 条，正好反了）。
    修法：判据写成"偏转 ≤ 180 − STRAIGHT_DEG"（内角 ≥150°）。
    **记法**：① 自检要断言**应用真实路径**（尤其是带缓存的那些），只测纯函数会漏掉一整类 bug；
      ② 自动判定那类代码的 bug 只在"内容更密更杂"的输入上暴露（拿 `board-baseline.md` 当对手盘）；
      ③ 缓存键必须跟着**排除集**走，"忘了给 key"要退化成不缓存。

26. **一条公式被手抄 14 处时，"导出的那份有自检、手指走的是复制品"。**
    2026-09-16 做架构 review 时，另一个独立走查指出：`worldToScreen` 存在但**在 `src/` 里零调用者**，
    而「屏幕 = 世界 × s + t」被手抄了 **14 处**（`BoardCanvas.jsx` 12、`Board.jsx` 2），
    `ctx.setTransform(dpr*s, …)` 同一公式写了两份，**捏合缩放还把 `clampViewScale` 与
    "以锚点缩放"的前馈公式又抄了一遍** —— 于是导出的 `zoomAt/clampViewScale` 有自检，
    真手指走的那条路却没有。这一类"口径不一致"**已经真的出过 bug**
    （框选"点线即选中"把世界像素当屏幕像素用，见上一节）。
    做法：收成一个 module `src/lib/view.js`（`worldToScreen` / `screenToWorld` /
    `worldRectToScreen` / `applyViewTo` / `viewTransformAttr` / `zoomAt` / `zoomBetween` /
    `panBy` / `centerOn` / `clampViewScale`），口径三条规矩写死在它的文件头：
    **一律纯浮点**（round 是"写 DOM"那一步的事）、**dpr 由 `applyViewTo` 乘**、
    **捏合的锚点用 `zoomBetween`（起点和落点是两个坐标）**。`board.js` 不再导出这四个函数。
    ⚠ 收口当场踩到一个坑，值得记：`worldToScreen` 返回的是 **`{x, y}` 不是 `{left, top}`**，
    我把它 `...` 展开进卡片的 `style` —— 卡片**没有 left/top**、静默退回 CSS 定位，整版错位。
    抓住它的是新加的那条跨层断言（拿 canvas 的变换反推视图，再用**同一个 module**
    算卡片该在哪，和它的 CSS `left/top` 比，Δ ≤ 1px；换一档缩放再比一次）。
    **记法**：同一个公式出现第二份时，就要问"测试打的是哪一份、手指走的是哪一份"。

27. **"自检只碰自己造的夹具板"曾经只是一句承诺 —— 而它每跑一次都在重写用户那张板。**
    2026-09-16 架构 review 的第三刀（C2）。9 个真浏览器自检各自抄了同一段胶水
    （CDP 会话 9 份、起浏览器 8 份、夹具板生命周期 6 份、退出清理 9 份），
    但重复的不是代码，是**纪律的漏点**：
    · **"打开的不是用户那张板"靠的是"进界面之后点左栏那一行"** —— 可应用在挂上界面
      **之前**就已经把"列表里第一个 `board-*.md`"读进来了，而中文名（`board-新白板.md`）
      在 zh 排序里排在 `board-zz-*` **前面**；冷字体缓存下应用还会按新规则重量卡片尺寸、
      写盘一次。于是每跑一次自检用户那张板就被重写一遍（内容不变，但 diff 是真的）——
      MEMORY 里那条"跑完 `git checkout --` 还原"就是这么来的：**靠人记得**。
    · **每个脚本都得自己记得"跑完删夹具"**，而"删的是谁的"全靠当时写对。
    · 起服务/浏览器是"脚本自己 spawn、自己 kill"，漏一个就是僵尸：改这一刀的当天就
      清掉了一棵树 —— 旧启动器 `.cache/run-board-browser.mjs` 留下的 headless Edge
      还在 9223 上听着，下一个自检会连上**它**（对着旧页面求值，绿得理直气壮）。
    做法：收成一个 module `scripts/lib/board-check.js`，对外只有 `withBoard(spec, body)`，
    它自己管四件事：
    · **夹具板的造/删** —— 名字只允许 `board-zz-<标签>.md`，**清理时名字对不上一律不删**
      （这条是"删的是谁的"那个坑的答案）。
    · **起服务 + 起浏览器 + CDP 会话**：真鼠标 / 双击 / 键盘 / 中键拖 / 笔（`penStroke`）。
      从前这几样散在 9 个脚本里，抄出来的差异就是漏点（"真鼠标"只有 2 个脚本有）。

      （第 16 条那个 1.5px 门槛），拿 mtime 判会天天假报警。
    · **"跑不起来"说人话**：端口上已经有服务/浏览器时**直接报红停下**（不然连的是旧进程）；
      body 抛异常也收成一次失败并照常收尾（不然挂在那儿，报出来是"自检不动了"）。

      绝不退回"列表里第一个"，那正是它要躲的东西。名字只跟 `/api/list` 的结果比，
      绝不当路径用（服务端另有 `SAFE_NAME` 那道闸）。

    拼别的查询（比如 `?paper=dots`）必须走 `open({ params })` —— 自己写 `APP + '?paper=…'`

## 荧光笔为什么是"一条路径一次描"

看 `src/lib/ink.js` 会发现荧光笔和笔走**完全不同的两条路**。这不是随手写的：

| | 笔 | 荧光笔 |
| --- | --- | --- |
| 画法 | 逐段 `beginPath + stroke` | **一条路径，一次 `stroke`** |
| 线宽 | 逐点跟压力变 | 恒定（`HL_WIDTH`） |
| 颜色 | 可选（黑/红/蓝/绿/紫） | 固定荧光黄 |
| 透明度 | 1（不透明） | 0.34（叠在字上） |

原因是**两件事叠加**让记号深浅斑驳（看起来像"笔刷质量差"，其实是画法问题）：

1. **半透明 + 逐段描 + 圆头**：段与段在圆头处重叠，透明色叠两次就变深。
   实测一道弯折的记号：逐段描的深浅标准差 **9.3**，一条路径描的是 **0.3**
   —— 31 倍的差别，肉眼一眼能看出来。`npm run check:highlighter` 量的就是这个。
2. **荧光笔也跟压力改线宽**：马克笔是一道**宽度恒定**的带子，
   一下粗一下细就是 bug。修在**存储层归一化**里（`normalizeStroke`），
   所以**老文件里画过的荧光笔下次打开会自动修好**，不用你重描一遍。

还有一条相关的：荧光笔的颜色和宽度都**钉死，不给你选**。
它的语义是"在已有的字上叠一层记号"，不是"用另一种颜色写字" ——
红色荧光笔盖在黑字上，字就读不清了。
（`check-board.js` 的 `[2b]` 钉着存储层这条，`check-highlighter.js` 钉着像素级的均匀度。）

## 笔记（第二个界面）

把一节课整理成 **量 → 公式 → 关系** 的树，公式输入不用背 LaTeX。
下面这一套是笔记界面的规则。

### 文件格式

一个 `.md` 文件 = 一节课 / 一周的总结。全都是纯文本，用记事本改都行。

```markdown
# 大物 · 电磁学（稳态磁场）

## 一、场怎么算出来

- 安培环路定理
  - 公式 | $\oint_L \vec{B}\cdot d\vec{l} = \mu_0 I_{\text{内}}$
  - 说的是 | 稳恒磁场中，B 沿闭合回路的积分只跟穿过的电流有关
  - 用到的量 | [[B]] [[mu0]] [[I]]
  - 题型 | 求无限长直导线、螺线管、螺绕环的磁场
  - 易错 | 只对稳恒电流成立

## 四、量

- [[B]] | 磁感应强度，T。矢量，描述磁场对运动电荷的作用能力
- [[mu0]] | 真空磁导率，$4\pi\times10^{-7}$ N/A²
```

三条规则：

1. **每行一个节点**，`- ` 开头。缩进 2 个空格 = 下一层。
2. 第一个 ` | ` 后面是正文。正文里的 `$...$` 渲染成公式。
3. **`[[名字]]` 是你亲手连的线。** 打 `[[` 会弹出补全，选一个就行。

`## 标题` 和 `- 项` 可以混着写，工具会自动把 `- 项` 挂到前面那个 `## 标题` 底下。

> **不想记格式：** 打开 `data/zz · 模板（复制这个来写新的一课）.md`，照着【】填空就行。
> 界面里的 **公式条 → `写法`** 页签也有同一份速查，不用离开页面。
> 文件名故意以 `zz` 开头：应用打开时载入列表里**第一个**文件，模板不能抢这个位置。

### 字段名：只认这几个

`公式` `定义` `说的是` `用到的量` `用到了` `题型` `方法` `易错` `注意` `什么时候能用`

定义在 `src/lib/parse.js` 的 `FIELD_KEYS`。想加词就往那个数组里加一个，两边一起生效
（着色层已经从那里 import，不再各留一份）。

**这不是"随便加"——写错的字段名不会报错，它会静默变成一个新节点挂在这一行下面**
（看起来像"内容掉下去了"）。要临时用别的词，就老老实实写成下一层小节点：
`- 什么时候能用 | 只对稳恒电流成立`。

## 连线是怎么算的

引用次数**只统计这两处**：

- `用到的量 | [[B]]` 这种字段行里的 `[[...]]`
- 正文里指向"量"那一支（标题含「量」的那一节）的 `[[...]]`

正文里其他地方写 `[[B]]` 只是**跳转**，不计入次数。这样你行文时可以随手加链接，不会把统计搞乱。

于是：

- **枢纽** = 被引最多的量（左边栏和色标里颜色越亮越是枢纽）
- **孤岛** = 一个公式都没用到的量。孤岛不一定是错的——可能是你还没想到它和谁有关。**这正是值得停一下的地方。**

## 编辑区：直接改，但看到的是渲染后的样子

以前是「上面原文、下面预览」两块——你得在下面看效果、在上面找地方改,两边对不上,而且阅读时被压成一小块。现在改成**两个整屏视图**:

- **阅读**:整屏只读,渲染好的树,想怎么翻怎么翻。**点任一节点直接切回编辑并跳到那一行。**

- **那一行上方浮出一个只属于这行的小气泡**,把行内公式用 KaTeX 渲染出来。

底下的状态栏显示「第 42 / 52 行 · 3 级标题 · 字段「公式」」。

顶栏还有个 **`专注`**:只亮着光标那一行,其余压暗,适合一晚上闷头整理。

> **为什么不做成 OneNote 那种彻底的所见即所得?**
> 那样就没法保证"你看到的就是文件里的内容",而且公式编辑会变得很别扭。
> 现在这个做法:字形是渲染的,内容永远是纯文本。
> 代价是「着色层」和「真正的编辑框」必须逐像素对齐,而且**折行位置必须完全一致**——
> `npm run check:align`(静态)和 `npm run check:browser`(真浏览器逐行比坐标)一直盯着这件事。

### 六个踩过的坑（改样式前先看这段）

都是"看起来能跑、实际错位"的类型,所以都写了检查盯着:

1. **行高不能用 px。** 实测:textarea 里写 `line-height: 37.75px`,字号 25.96px 的标题行盒
   **仍然只有 37.75px**——大字被压扁,和光标错位。改成无单位 `1.95` 后,
   行盒 = 字号 × 1.95,标题行自动变高。所以 `--src-lh` 是**无单位倍数**,不是 px。
2. **`.hl-line` 不能用固定 `height`。** 长公式行本来就该折行(示例里第 5 行文本宽 901px >
   可用 793px)。锁死高度的话,折下来的那截会溢出到下一行,**两行叠字**。用 `min-height`。
3. **`.hl-line` 必须用 `content-box` + 负 margin。** 用 `border-box + padding` 会吃掉
   6px 文字宽度,两层折行点就不一致了。
4. **标题行的光标得自己画。** 一个 textarea 只有一个字号,浏览器画的原生光标也只按这个
   字号算几何。实测(`scripts/caret-shot.js`):

   | 层级 | 字号 | 原生光标高 | 原生光标顶(相对内容盒) | 字形顶 |
   | --- | --- | --- | --- | --- |
   | 正文 | 19.375px | 23px | 8px | 8px ✓ |
   | lv1 标题 | 29.06px | 34px | 2px | **11px ✗ 差 9px** |

   所以标题行把原生光标藏掉(`.srcbox.custom-caret .raw { caret-color: transparent }`),
   改用一个按**该行自己的字号**算高度、纵向居中在行盒里的自绘竖条。
   正文行仍然用原生光标(它本来就是对的)。
5. **行底色不能用 `background-color`。** 折行的行,第二行及以后的文字会落到色块外面
   (色块高度只按第一视觉行算),看起来就是"字跑出色块"、和下一行的色块挤在一起。
   必须用 `repeating-linear-gradient` 按 `--src-lh` 重复铺
   (见 `.hl-line.active` / `.hl-line.field.*`)。
6. **那个 textarea 是非受控的，所以"从白板切回来"时要自己把文本灌进去。**
   它刻意不写 `value={text}`（受控会让 React 在打字时重渲染抢光标），
   平时靠 `App.open()` 里那句 `taRef.current.value = shown` 直接写 DOM。
   但**从白板切回笔记**时 `SourceEditor` 还没挂载 —— `taRef.current` 是 null，
   那句就静默落空了：着色层有字、编辑框是空的。用户往空框里打一个字，
   `onEdit` 拿到的就只有那一个字，**整篇被覆盖（丢数据）**。
   实测：切过去之后 `ta.value.length = 0`，而 `.hl-line` 有 52 行 ——
   `cdp-caretfit` 因此报「行号无效：文件没有可用内容（共 1 行）」。
   现在 `SourceEditor` 自己有一个挂载 effect 兜住这件事。

> 顺便记一个教训:**类名不要复用。** 工具条的展开箭头一度也叫 `.caret`,和自绘光标
> 撞了名。`npm run check:align` 现在会盯着这件事。

> 还有两个"自检自己骗自己"的坑，都修了，改自检的时候别再犯:
>
> - **`check:mount` 曾用 `readdirSync(data)[0]` 取样本。** Windows 的 `readdir`
>   不保证顺序，`data/` 里多一个 `.md`（那份填空模板）就被选成样本——
>   于是"加载的是 B，却假装自己是 A"，后面所有断言都在拿错内容比对，
>   **报出来的错全是假的**（一次假报 4 条）。现在按内容里的标记显式挑样本，
>   挑不到就立刻退出。
> - **预览曾静默丢掉认不出的正文。** `- 关系名 | 说明` 这种两边都不是字段名的写法，
>   `|` 后面那半句一个字都不显示，看起来像"格式没生效"。
>   现在认不出来就当普通说明渲染——**宁可丑，不可丢**。

## 公式怎么打

顶部常驻公式条，点了就插到光标处，**不用打 `$`**（两端自动补）。

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl` + `/` | 分式，光标自动进分子，`Tab` 跳到分母 |
| `Ctrl` + `2` | 上标 |
| `Ctrl` + `_` | 下标 |
| `Ctrl` + `Shift` + `R` | 根号 |
| `Ctrl` + `Shift` + `V` | 向量箭头 |
| `Ctrl` + `Shift` + `+` / `-` | 整体放大 / 缩小字号 |
| `Tab` | 跳到下一个空位；没有空位就缩进整行 |
| `Shift` + `Tab` | 反缩进 |
| `Enter` | 自动续 `- `，保持缩进 |
| `Ctrl` + `S` | 保存 |
| `[[` | 触发引用补全，`↑↓` 选，`Enter` 确认 |

**选中文字再点工具条按钮 = 把它包进公式里。** 比如选中 `mu0` 再点 `√`，直接变成 `$\sqrt{mu0}$`。

公式渲染用 KaTeX，数学模式里写中文要包 `\text{}`：`I_{\text{内}}`。

## 数据 / 备份

- 数据目录：`data/`，一个总结一个 `.md` 文件。
- 服务是**原子写**的（先写临时文件再改名），写一半断电不会留下坏文件。
- 你可以用 VSCode 直接改 `data/` 里的文件；页面检测到磁盘变了会提示你点「重载」。

### 备份到 GitHub

仓库：**https://github.com/AK47n/studyhelper**（**公开**）。`data/` 里的笔记也在版本控制里，
所以换电脑、误删、改坏了，都能从 GitHub 找回来。

> ⚠ **公开 = 谁都能看。** 这里曾经写成"私有"，但仓库其实是 public
> （2026-09-15 用 `gh repo view --json visibility` 实测确认）。既然 `data/` 跟着进 Git，
> 那些笔记就等同于是公开的，也包括被搜索引擎抓到。
> 别往 `data/` 里放不想公开的东西；真要转私有：`gh repo edit --visibility private`。

写完之后**双击根目录的 `备份到GitHub.bat`**（或者 `npm run sync`）。它会：
提交 → 拉取（`--rebase`，避免两台机器写出分叉）→ 推送，任何一步失败都会说清楚卡在哪。

```
  studyhelper 备份到 GitHub
  ─────────────────────────────────────
  改动清单：
  M  data/示例 · 大物电磁学.md
  M  README.md
  ✓ 已提交
  ✓ 已同步远端
  ✓ 已推送到 GitHub
```

**提交信息会写清这次改了什么**，不再是清一色的「笔记更新 \<时间\>」：

```
笔记更新 2026/9/15 23:40（2 个文件）        ← 主题：时间 + 文件数

⚠ 这次不全是在 data/ 里写笔记 —— 上面这些里面有代码 / 脚本 / 文档。
  （「笔记更新」是这个脚本一直以来的名字，不代表这次只改了笔记。）

改动清单（git status --short）：
  M  data/示例 · 大物电磁学.md
  M  README.md
```

为什么要这么啰嗦：以前改了 35 个文件（里面有白板图层修复）和"改了一篇笔记"在
`git log` 里长得一模一样，回头看历史分不清哪次是代码。现在主题带文件数、
正文是完整清单，动了 `data/` 之外的东西还会明说一句。
中文文件名也不再被转义（`core.quotepath=false`，否则是 `data/board-\346\226\260…`）。

> 拿清单的办法有点绕，是因为这脚本有一条硬规矩：**不捕获 git 的管道输出**
> （见 `scripts/sync.js` 文件头第 2 条）。所以 `gitToFile` 把 stdio 的第二项给一个
> **打开的文件描述符**，git 直接写盘、脚本读盘。万一拿不到（受限环境、权限），
> 就退回老样子——主题只写「笔记更新 \<时间\>」，**备份照样做完**：
> 信息少一点可以，不能因为想问清楚"改了啥"而备份失败。
>
> 顺带修掉一个**静默漏备份**：判据从 `git diff-index --quiet HEAD` 改成
> `git status --porcelain`。前者只看已跟踪文件的改动，**看不见新文件** ——
> 从别处拷进来一篇新笔记、或者应用新开了一张板（`data/board-*.md` 就是新文件），
> 旧判据会说「没有新改动」然后什么都不提交。

换台电脑继续写：`git clone` 下来，`npm install`，`npm run build`，然后照旧双击启动。

> 已知的小摩擦：这个 .bat 是双击用的，所以**它不会自动跑**。想省掉这一步，
> 可以让服务在每次保存后自动推一次——没做，是因为那会在后台悄悄动你的 GitHub 账号，
> 得你点头再加。

**动了纸面（背景、`paper-*` 那几档 CSS、工具条上的「背景」按钮、`paperGeometry`），
跑 `npm run check:paper`。**
它是自足的：自己起服务（5201）和 headless Edge（9231），跑完都收掉，
全程只碰自己造的夹具板 `board-zz-papercheck.md`（一张空板，跑完删掉）。
和上面那条同一个道理 —— 纸面坏了不报错、也不影响画和存，只有"看一眼屏幕 / 量一下数字"才知道，
所以它里面有像素证明和几何证明那两节。

**动了卡片的行为（拖动 / 选中 / 手柄 / 固定 / 双击进编辑），

所以 `check-lock.js` 一律用真鼠标，而且每条动手之前先问 `elementFromPoint`。
它同样自足（服务 5202 + Edge 9232 + 夹具板 `board-zz-lockcheck.md`）。

**动了"打开哪一个"的逻辑（`App.jsx` 的首次加载、`ensureBoard`、`/api/list` 的排序），
跑 `npm run check:default`。** 它要的前提是 `data/` 里没有 `board-*.md`；
有的话会直接跳过、**不碰你的任何文件**。

**改了手写识别（包括"美化手写"和"框选认公式"），跑 `npm run check:ocr`（快、离线）和 `npm run check:ocr-browser`（慢、但真的画一遍）。**
后者会起一个假的识别服务，所以**不需要真密钥、不联网、不花额度**，
而且它会检查"我们到底发出去了什么"（是不是 PNG、鉴权头对不对、地址对不对、
**发的是认公式那段提示词还是认文字那段**）。
它还会走一遍完整的「框选 → 美化 → 文字卡」：断言那个浮出来的「✨ 美化」按钮
**真的点得到**（`elementFromPoint`）、落下来的卡片**落在你圈的那块笔迹的左上角**、
而且**宽高都只剩内边距**（"贴合内容"，不再去盖原笔迹）、
原笔迹一笔都没少、`Ctrl+Z` 能连同"擦掉的笔迹"一起退回去，
再走一遍「框选 → ∑公式 → 公式卡」并量卡片的留白（"卡高 − 内容高 ≤ 16px"），
最后截几张图（`.cache/beautify-shot.png`、`card-interact.png`、`formula-from-ink.png`）
让人自己看一眼。

> 它会**自己造一张夹具板**（`data/board-zz-ocrcheck.md`）再动手 ——
> 因为它中途会往白板上插一张卡片，不能插到你的板上（这条踩过，见白板踩坑第 10 条）。
> 它对 `config/ocr.json` 也是"先挪开、跑完放回去"：
> 你有配置就还给你，没有就只删它自己写的那个假配置。
> ⚠ 曾经写成"恢复之后又无条件删掉"，等于**跑一次自检就把你的密钥删了**（2026-09-15 真发生过）。

> **`check:loaded` 也是同一条规矩，而且它是 2026-09-16 才补上的。**
> 它要"真的画一笔"才能证明笔能用，而它原来画在**打开时列表里第一个板**上 ——
> 那多半是你自己的板。实测那次它的落点算到了**底部工具条的按钮**上
> （打印出来是 `bd-t on`）：那一下不是在画，是点了一个工具 ——
> 点到橡皮的话，后面那串 `mouseMoved` 就变成了**擦你的笔迹**。
> 现在它开的是 `?file=board-zz-loaded.md`（应用直接从 URL 打开夹具，**不会读你那块板**），
> 而且**落点不是 `.bd-hit` 就不画**（测不到就明说"跳过"，不在板上乱点）。
> 记法：**会写数据的自检，先给自己造一张夹具板；会点屏幕的自检，先问 `elementFromPoint`。**
