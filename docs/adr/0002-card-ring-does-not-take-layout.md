# 卡片那一圈不进布局：世界坐标的尺寸里不许混进屏幕像素的量

**状态**：已定（2026-09-17）

卡片（`.bd-card`）外圈那一圈**不再用 `border`，改成 `outline`**
（`--bd-ring` + `outline: 1.5px solid var(--bd-ring)` + `outline-offset: -1.5px`）。

理由只有一条：**卡片的 `w`/`h` 是"世界坐标"的量**（存进板文件；`cardWidthFromContent`
把屏幕上量到的数除以 `s · scale`），而 `border` 是**屏幕像素**、不跟缩放走。
一个屏幕像素的量只要混进那一圈，卡片就**只在"量尺寸那一档缩放"上**贴合内容：
换个更小的缩放档，内容盒会比内容窄 `圈的总宽 × (1 − s/s0)`，
一过 0.5px，`.bd-tex` 的 `overflow-x: auto` 就换来一条 12px 的滚动条 ——
屏幕上是「卡片底下一根**恒粗**黑线」，外加 12px 的撑高。
`outline` **不参与布局**，那一圈就不再是世界坐标尺寸的一部分，缺口恒为 0。

**这条规矩往外推**：往卡片上再加任何量之前，先问它跟不跟缩放走。
跟的（字号、内边距、圆角 —— 都乘 `--bd-card-scale`）可以进那一圈；
不跟的（角上那几颗手柄的 18 / 22px、选中那圈 3px 光晕、outline 本身）**一律不许参与布局**
（手柄是绝对定位在框外的，光晕走 `box-shadow` —— 它们本来就不占布局，是这条规矩的正例）。

**这条规矩住在哪**（2026-09-17 补）：`view.js` 的 `combinedScale(s, k)` 出一个倍率，
`worldLenToScreen` / `screenLenToWorld` / `scaledRectToScreen` 负责两个方向 ——
**那个倍率只有一处乘**（卡片渲染、缩放柄、量尺寸的 `wantW` 都走它）。
在这之前它是手抄在三处的，而"两边各算"正是下面那根黑线的成因。

## 为什么（实测）

1440×900、dpr 1、公式卡 `\oint \frac{1}{z-2} dz = 0`、量尺寸那一档 s0 = 1.451：

| 缩放 s | 1.451 | 1.0076 | 0.8397 | 0.4859 | 0.4049 |
|---|---|---|---|---|---|
| 缺口（正 = 内容盒比内容窄） | −0.17 | +0.45 | +0.67 | +1.31 | +1.36 |
| 横向滚动条 | 无 | 无 | **12px** | **12px** | **12px** |

- 缺口就是 `圈的总宽 × (1 − s/s0)` —— 边框是"屏幕像素"却按"世界像素"存了一次，逐档验算对得上。
- 滚动条出现后**还吃掉 12px 布局高度**：s = 0.84 时卡高 67.08 → 79.08，
  "贴合内容"（README 第 15/16 条）当场破功。
- 换成 outline 之后同一张卡在同一批缩放档上是 **−0.23 … −0.03**（永远"多给一点"），
  溢出恒为 0、任何档都不出滚动条。
- 它还是个**棘轮**：重开板时会在当前缩放下重量一次（那一刻缺口为 0、线消失），
  再往小缩 ~25% 又长回来 —— 所以"我上次看没有"证明不了什么。

## 被否掉的替代方案

1. **让边框跟着缩放走**（`border-width: calc(1.5px * var(--bd-card-scale))`）：
   不行。Blink 把边框宽度**向下取整到整像素**，缺口只是变小、并不消失 ——
   实测缩到 s ≈ 0.40 照样冒 12px 黑线。
2. **只让滚动条不占位、不画**（`scrollbar-width: none` + `::-webkit-scrollbar { height: 0 }`）：
   治的是症状。内容照样被挤窄，只是不再有一条假的提示把它显出来。
   （**这一条还是做了**，但定位是"第二道闸"，见"后果"。）
3. **`overflow: hidden`**：不行 —— 那会把那几像素**真的裁掉**，
   就是 `E = mc²` 少个 c² 那个坑（README 第 15 条）。硬判据必须留在
   `scrollWidth > clientWidth` 上，它要求 `overflow-x` 仍然是 `auto`。
4. **把圈算成世界像素 / 给卡片留点余量**：不行。需要补的缺口是 `圈的总宽 × (1 − s/s0)`，
   而 s → 0 时它**无界**（等价地：世界坐标里要补 `圈宽/s`）——
   存盘的是一个数、缩放可以到 0.15，一个常数兜不住所有缩放档。

## 后果

- **卡片少了 2px**（1px×2 的边框不再占布局），内容一点没变 ——
  字离那圈近了 1px。观感不变：outline 跟着 `border-radius` 走，
  负的 `outline-offset` 把它画在原来那条边框的位置上。
  （截图读像素验过：卡片最外那 1px 还是 `#e2d9bc`，往里就是卡片底色 `#fffdf4`；
  同一张图里一个滚动条拇指色 `#262e3d` 的像素都没有。）
- **圈的颜色仍分卡、分选中态**，只是从 `border-color` 换成自定义属性 `--bd-ring`
  （`.is-formula` / `.is-note` / `.on`）。层叠顺序**照旧**，所以
  "选中的公式卡那圈是什么颜色"这个行为一个字没变；选中反馈一直是那圈 3px 蓝光。
- **`.bd-tex` 那两行留着**（滚动条不占位、不画）：第二道闸，不是根治。
  理由是"少一点点"这种几何错肉眼查不出来，而它一犯就是一根 12px 黑棒 + 12px 撑高。
- **`sampleCardForFit` 照样读 `borderWidth`**（现在读到 0）、`padPx` 的换算一个字没改：
  这条换算对"圈"必须通用 —— 谁哪天把 border 加回来，它照样算得对，
  但**那个人要负这条 ADR 的责任**。
- **自检**：`check:refit` 的 [3] 把这条规矩钉住了 —— 真鼠标点工具条那颗「画布缩小」，
  从量尺那一档一路缩到 33%（再缩回来两档），每一档断言
  ① 卡片给内容留的位置 ≥ 内容自然宽；② `scrollWidth ≤ clientWidth`。
  ⚠ 判据**只能是几何**：所有真浏览器自检都带着 `--hide-scrollbars`
  （`scripts/lib/browser.js`），滚动条类的东西在那一族自检里天生不存在 ——
  这条黑线就是这么从 9 条自检底下溜过去的。别把它改成"截图上看得见"。
