# 连接是宣告的，不是猜出来的

**状态**：已定（2026-09-17）

白板上"两样东西之间的关系"不再由应用从**笔迹形状/位置**里猜，改由你**显式宣告**：
工具条上一颗「→ 箭头」工具，划一笔（**一次性**，画完自动回笔），两端吸附到最近的**板框**或**卡片**，
这一条连接写进板文件的 `links`；屏幕上那条箭头是**应用合成的**（两点之间一条规整的线 + 一个尖），
框一动它就跟着动。

**板框**（`frames`）是你框选之后亲手留下的一个整体：成员（笔迹 / 卡片）在**留下的那一刻定死**，
框线按成员的包围盒 + 内边距**现算**，可以整体拖动、有标题（"这一节是什么"）。

## 为什么

2026-09-17 拿三张真板（494 / 439 / 620 笔）量的：

- **形状判据的误报率 ≈ 100%**：被判成"箭头"的 92 条笔迹里，**没有一条是箭头** ——
  直度中位 0.28、`findTip` 报的张开角中位 ~20°（还有 0.3° 的），
  而真人手画的箭头是"杆 51~59px 笔直、两臂张开 107°"。`findTip` 认下来的是**汉字折笔的拐角**
  （"的/夕/匀/分/数/了"的撇、钩、环、连笔）。用户的原话：「我这里面一个箭头都没有」。
- **三张板读出来的连接都是 0 条**。也就是说"零步骤优先"（README 第 7 行那句卖点）
  在真实输入上**既没给过东西，也没给对过东西**。
- 用户真正画在两坨公式之间的那些线，卡在**位置三道闸**上（够长 ≥48px / 中段空白 ≥18px /
  两头落在不同的块里）—— 跟"箭头"无关，所以"只砍形状判据"救不了他。

## 被否掉的替代方案（都量过或想过）

1. **保留自动、只放宽阈值**（中段空白 18 → 12）：那张板上确实会"冒出"5 条连接，
   但逐条看图，救回来的同样不是箭头（一条 62px 的直线是从旁边一个字上拐出来的笔画）。
   性质与形状判据一模一样 —— **调参赌手感**，不解决问题。
2. **半自动**（保留"两端顶到东西上就算相关"，只砍"形状 → 因果"）：他的箭头仍然过不了三道闸，
   等于 0 条 —— 那正是这次抱怨的原点。
3. **粘住的箭头工具**：否掉。用户的用法是「两个板块画完，连一笔」，不是连续连很多笔；
   一次性少一次回切。用笔的人给 `A` 快捷键，手不用离开纸。
4. **框的成员按位置自动并入**：否掉 —— 那又变回位置猜，正是这次的整个教训。
5. **框存矩形坐标（像卡片）**：否掉 —— 框必须是**内容的函数**，否则内容一挪框就飘，
   "形成一个整体"当场变假。
6. **把框做成"卡片"**：否掉 —— 卡片的宽高是**按它的内容量出来的**（`card-fit.js`），
   框的尺寸是**成员包围盒**的函数；两套尺寸语义混在一起会互相推。两个名字，一套拖动/缩放的手感。

## 后果（照实记下来）

- **"连接"第一次成为存盘的东西**（`links`）。今天它是零字节、纯现算 ——
  所以擦除、撤销、删框/删卡都要立规矩：**死 id 不留尸体**（和 `groups` 同一个纪律）。
- **「不算连接」删除**：它是专门给"猜错了"配的否决权，猜没了它就没有对象。
  那排词里 `0` 那颗位置改成「**删掉这条连接**」。
- **条件那一族保留**（位置送 + 两个手动口子），所以"中点旁边那撮字"这块**最小聚类**留着；
  砍掉的是"候选线 → 排除集 → 重聚块"那条链。
- **「卡↔卡画一条线即成立」这条免费路保留**：它不看形状、不过闸，是这堆机制里
  唯一没有假阳性的部分。
- 老文件里由旧判据读出来的连接，用**一次性迁移脚本**落成显式记录，跑完即删脚本；
  旧检测代码**不留在应用里**当第二份真相。
- **分期**：第一刀 = 本 ADR + 数据层（`frames` / `links`）+ 板框界面；
  第二刀 = 箭头工具 + 砍掉形状判据/三道闸/候选线排除集 + 迁移 + 重写文档。
