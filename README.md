# studyhelper · 过手总结台

两种界面，一个工具：

| | 干什么 | 一句话 |
| --- | --- | --- |
| **白板**（默认） | 拿笔就画。写公式、写名字、画箭头，**关系靠位置自己出来** | 不用记任何格式 |
| **笔记** | 把整理好的东西收成「量 → 公式 → 关系」的树 | 适合最后通一遍 |

**数据是你硬盘上的纯文本文件，白板文件永远不上传。**
唯一会联网的是「手写公式识别」这一个动作：点了它，**那一张手写的图**会
发到识别服务去转成 LaTeX。不用它就完全不联网，其它一切都在这台机器上。
默认用 DeepSeek 的视觉模型（你已有的 key），也可以切到 SimpleTex。
（密钥只存在本地 `config/ocr.json`，浏览器从来没见过它。详见「手写公式」。）

> 两个界面是**独立的两套文件**（白板叫 `board-*.md`，笔记叫别的 `*.md`），
> 左边栏的「✎ 白板 / ▤ 笔记」切换。打开软件默认进白板 —— 因为它才是"打开就能用"的那一个。

## 怎么跑

**双击桌面上的 `studyhelper` 快捷方式** → 起服务（**不弹黑窗口**）→ 打开浏览器。

**关掉浏览器标签页，服务自己就停了。** 你不用再"先关服务"。

怎么做到的：页面每 5 秒给服务发一次心跳；正常关标签时页面还会用 `sendBeacon`
当场告别一下，所以**大约 1 秒就收摊**。没来得及告别的（浏览器崩了、被强杀）
最迟 15 秒也会停。两条保险避免误杀：

- **从没收到过心跳的服务永不自动退出** —— 命令行 `curl`、自检脚本、`npm run dev` 都不受影响；
- 按 `F5` 刷新不会误杀：告别之后有 2.5 秒宽限，新页面在这期间报到就作废。

> 想让它常驻别自动退：`node server.js --no-auto-exit`（或设 `STUDYHELPER_AUTO_EXIT=0`）。

### 那个桌面图标是干啥的

它是个**开关，也是兜底**：

| 现在的状态 | 点一下会怎样 |
| --- | --- |
| 没在跑 | 起服务（无黑窗口）→ 打开浏览器 |
| 正跑着 | 停掉服务、释放端口 → 换一张「已停止」提示页 |

平时你根本不用点它第二次——关标签就够了。它是给这几种情况留的：
浏览器崩了/被强杀了导致服务变孤儿、你想马上收摊、或者只是想确认它在不在。

> 也可以不用快捷方式：`启动 studyhelper.bat` 会**在前台**起服务
> （黑窗口看得见，关掉窗口就等于关掉服务）。
> 想改代码看实时刷新：一个终端 `npm run dev`（前端 5180），另一个 `npm start`（后端 5177）。

### 这套启停脚本踩过的坑（改之前先看）

都在 `scripts/` 和 `server.js` 里，全是"看起来能跑、实际不行"的类型：

1. **`.ps1` 必须带 UTF-8 BOM。** PowerShell 5.1 对无 BOM 的 `.ps1` 按本地代码页（GBK）读，
   中文注释被解成乱码、引号被吃掉 → **整个脚本解析失败、什么都不做**，还不一定报错。
   ⚠ 用普通编辑器改完这些文件，BOM 可能会掉，改完就点一次快捷方式验证。
2. **别用 `taskkill /T` 杀服务。** 我们是用「隐藏窗口的 powershell」起 node 的，
   `/T` 会顺着进程树往上爬，把**调用它的那个 shell 也杀掉**（实测：调用方拿到 exit code -1，
   后面的验证代码一行没跑）。现在只杀监听端口那个进程本身，并且把本脚本的祖先 PID
   拉进白名单，命中就跳过。
3. **别在读注册表后不还原"当前位置"。** dot-source 进来的脚本，位置是共享的：读完 `HKLM:`
   不回文件系统，调用方后面的 `Start-Process -FilePath` 会报
   `current provider (Registry) cannot open a file` —— 报错位置和注册表看起来毫无关系。
   现在改用 `Microsoft.Win32.Registry::GetValue`（纯 API），压根不碰位置。
   （`Push-Location`/`Pop-Location` 包起来实测**没用**。）
4. **`$ErrorActionPreference='Stop'` 会把原生命令的 stderr 当致命错误。** vite 会往 stderr
   打一条 "chunk 超过 500 kB" 的提示 → 被升级成终止性错误，表现为
   "构建退出码 0、dist 正常，脚本却报构建失败"。跑原生命令时要临时放成 `Continue`，
   并且只信 `$LASTEXITCODE`。
5. **窗口标题不能要求"精确相等"。** 浏览器会在页面标题后加自己的名字
   （`studyhelper 已停止 - Google Chrome`），所以关提示窗口要用**前缀**匹配。
6. **想自动关掉浏览器标签页？做不到。** 试了 4 轮：`SetForegroundWindow` 成功、前台确认到了
   Chrome、同一手法发 `Ctrl+T` 能开新标签、`Ctrl+Tab` 能切换标签，**但 `Ctrl+W` 就是不动**。
   所以改成导航到一张「已停止」提示页。别再折腾按键关了，这个坑不值得再踩一遍。
7. **自动退出要能测，所以留了两个旋钮**：`STUDYHELPER_AUTO_EXIT_MS`（心跳断多久算断）
   和 `GET /api/state`（把 `lastHeartbeat` / `byeAt` 直接吐出来）。
   没有这两个，这类"什么时候退"的问题只能靠猜——我实测时就因为看不清内部状态，
   一度把自己的测试设计错误误判成功能有 bug。
8. **绝对不要用 PowerShell 的 `Set-Content` / `Add-Content` 改这个仓库里的文本文件。**
   它按本地代码页重编码，**整个文件的中文当场变乱码**。实测连续踩了两次
   （`scripts/check-board.js` 和 `scripts/check-board-browser.js`，都是这仓库的源码）。
   `Out-File` 同理。要改文本就老老实实用编辑器，或者 `node -e` 读写。
   这和上面第 1 条是同一个根因的两个方向：**PowerShell 的默认编码和我们的文件不一致。**

## 白板（默认界面）

打开的是一张**无限大的纸**，一节课一页。手写笔直接画，不用点任何按钮。

### 画

| 想干什么 | 怎么做 |
| --- | --- |
| 写字 / 写公式 / 画箭头 | 拿笔直接画（默认就是笔） |
| 擦掉 | 点「◻ 橡皮」再画，或按 `E`；碰到哪一笔就擦掉**整笔** |
| 做记号 | 点「▬ 荧光」 |
| 平移 | 手指拖 / 中键拖 / 按住空格拖 |
| 缩放 | 两根手指捏；或者滚轮；触控板双指也行 |
| 把所有内容装回屏幕 | `Ctrl` + `0`，或点工具条上的 `⤢` |
| 撤销 / 重做 | `Ctrl` + `Z` / `Ctrl` + `Shift` + `Z` |

**手写笔永远只画画，手指永远只平移缩放。** 这是特意做的：在 Surface 上写字，
手掌蹭到屏幕是常态；如果手指也能画，你每写一行就会多出一条莫名其妙的线。

### 公式：写个大概就行

点工具条上的「**∑ 公式**」放一张公式卡，双击进去写，**按你顺手的样子写**：

| 你这样写 | 它变成 |
| --- | --- |
| `F = ma` | F = ma |
| `dS/dt` | 排成上下分式 |
| `B = mu0 I / (2 pi r)` | 分子 μ₀I、分母 2πr 的分式 |
| `sqrt(x^2 + y^2)` | 根号 |
| `mu0` | μ₀（下标自动出来） |
| `N/A^2` | N/A²（**不**排成分式 —— 这是单位，不是除法） |

卡片下方还有一排按钮（`a/b` `√` `xⁿ` `xₙ` `μ₀` `∫` …），点一下就插到光标处。
**它们插进去的是上面那种写法，不是 LaTeX** —— 面板和手写是同一套语法，
不会出现"面板插的东西我自己看不懂、也没法改"。

两条底线：**认不出来的东西一律原样留着**（宁可丑，不可丢）；
**转化两次等于转化一次**（不然每次重排都可能悄悄改坏内容）。两条都有自检钉着。

> **能不能直接手写公式、自动认出来？** 能，见下面一节。这一条最初是"不做"的
> ——理由是它必须联网，和"不联网、不上传"冲突。后来改了主意：允许联网，
> 但把边界划清楚 —— **只有你点「识别」的那一张图会发出去**，白板文件本身永远不上传。

### 手写公式：写在纸上，它给你排好看

懒得想"该打什么"，就直接写。工具条上的「**✍ 手写公式**」（或按 `W`）打开一块写字板：

1. 拿笔在里面写一个公式（写大一点更准）；
2. 点「识别」；
3. 认出来的式子会**渲染出来**，下面还有一个可以改的输入框；
4. 满意了点「放到白板上」→ 白板上多一张公式卡，并且直接进编辑态，随时能再改。

默认走 DeepSeek 的视觉模型（用你已有的 key）；也可以切到专门认公式的 SimpleTex。
配一次密钥就行，见下面。

几个刻意的设计，都是取舍过的：

- **写字板是单独一块，不是"圈住白板上的字去识别"。** 白板上的字是你思考的痕迹，
  位置和大小都有意义；识别后就地替换掉，你会失去"我当初是怎么写的"。
  代价是多一次点击，换来的是白板上的东西永远是你自己放上去的。
- **一次只写一个公式。** 识别服务是"一张图 → 一个 LaTeX"，写两个它会串在一起。
- **认出来先进可编辑框，不直接变卡片。** 识别是帮忙，不是替你做决定。
- **置信度低会明说**（"这次不太准，多半得手动改两笔"）。
- **底部会告诉你"会发一张多大的图"**。发出去的东西你该看得见。
- **只写 `tex`，不动 `src`。** 识别结果进的是"显示用的式子"那个字段，
  你手打的那串留着不动 —— 以后双击进卡片时，"我原来写了什么"这个参照还在。

#### 要配一次密钥

默认走 **DeepSeek 的原生多模态模型**（`deepseek-flash`）—— 好处是**用你已经在用的那个
账号和 key**，不用再申请一家。手写公式识别也能用另一家专门的服务，设置里切一下就行。

| 用哪家 | 要什么 | 特点 |
| --- | --- | --- |
| **DeepSeek**（默认） | DeepSeek 的 API Key（`sk-` 开头） | 用你已有的账号；图片发到 api.deepseek.com |
| SimpleTex | SimpleTex 的鉴权串（UAT / APP） | 专门认公式，手写更对路；有每日免费额度（轻量模型每天 2000 次） |

配置步骤（两家一样）：

1. 点「✍ 手写公式」→ 提示里点「去设置」（直接点识别也会自己把设置摊开）；
2. 选一家，把密钥**原样**粘进去；
3. 保存 → 点「测试一下」。

> **模型名会变，所以它是配置项。** DeepSeek 官方已经把
> `deepseek-v4-flash-vision-exp` 标成下线（虽然还能调，但请求由最新的 Flash 承接），
> 现在写的是 `deepseek-flash`。哪天名字再变，在「高级」里改一下即可，不用等改代码。
> 见 [DeepSeek 图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision)。

密钥存在 `config/ocr.json`，这个目录在 `.gitignore` 里 ——
**不会被备份到 GitHub**。换电脑要重新填一次。

#### 想换成自建服务 / 别的服务？

设置面板里有「高级」，改**接口地址**（和模型名）就行。两条路的契约：

**DeepSeek（OpenAI 兼容）**

```
POST {dsBase}                 # 默认 https://api.deepseek.com/chat/completions
Header: Authorization: Bearer <key>
Body:   { model, temperature: 0,
          messages: [ { role: 'user', content: [
            { type: 'text',      text: '<只输出 LaTeX 的指令>' },
            { type: 'image_url', image_url: { url: 'data:image/png;base64,…' } }
          ] } ] }
返回:   { choices: [ { message: { content: "..." } } ] }
```

`content` 必须是**块数组**（写成字符串会被 400）。
模型回的话会被清洗一遍：剥掉 ```latex 围栏、剥掉 `$`、抠出"公式是：xxx"里那句，
回一句中文解释时**当没认出**（绝不把中文塞进卡片）。

**SimpleTex（专门认公式）**

```
POST {base}{|_turbo}          # 默认 https://server.simpletex.net/api/latex_ocr
Header: token: <你那一整串>
Body:   multipart/form-data，字段名固定 file（PNG/JPEG）
返回:   { "status": true, "res": { "latex": "...", "conf": 0.95 }, "request_id": "..." }
```

那一整串是原样发出去的，我们不替你加前缀 —— 鉴权串本身就是"前缀 + 密钥"接在一起的
完整串，替你拼只会拼错。头名字也能在配置里改（`tokenHeader`）。

#### 失败的时候会说人话

原因**分开报**，因为下一步完全不同：

| 界面上的字 | 什么情况 | 该做什么 |
| --- | --- | --- |
| 还没配密钥 | 没填 | 去设置填 |
| 密钥不对 | 401 / 403 | 去设置重填 |
| 额度用完或被限流 | 429 | 等一会儿；余额不足（402）会把对方原话带出来 |
| 连不上识别服务 | 网络 / 超时 | 查网络；写的东西还在，好了再点一次 |
| 没认出内容 | 服务通了但没内容 | 写清楚点、写大点 |

识别是**可选**的：没配密钥、断网、服务挂了，白板和笔记照常用，
只是识别报一句人话。绝不会因为识别失败而丢东西。

### 关系：不用你填，是"读"出来的

这是白板和笔记最大的区别：**你没有"关系"这个字段要填。**

点「▤ 便签」放一张便签，把公式卡放到它**旁边**或者**摞在它上面**，
右边「关系」面板就会自己列出谁属于谁。判定顺序（从强到弱）：

| 你怎么摆 | 它算成 |
| --- | --- |
| 公式卡整个落在便签**里面** | **包含** —— "这公式属于这一节" |
| 两张卡搭在一起、差不多大 | **重叠** —— 相关 |
| 两张卡离得不远（26px 以内） | **挨着** —— 手写的人就是这么表达的 |
| 谁都不挨着 | **孤岛** —— 不一定错，可能正是你还没想清楚"它属于哪一节"的地方 |

面板上会写「按位置读出来的」，这是**故意说清楚的**：这是推断，不是你说过的。
想让它变成确定的，就用笔在两张卡之间画一条线 —— 那条线会被认出来（面板里标实线的就是它）。

> **为什么不用"你必须画个框、连根线"那套？** 因为那又变成要你学一套规矩了。
> 位置本身就是关系 —— 这也正是白板比大纲强的地方。

### 别按 Ctrl+S

**白板是自动存的**（停笔 0.7 秒后写盘）。工具条右下角那个「已存 / 正在存…」就是它。
切文件、关页面之前还会补存一次。

### 数据长什么样

一张板 = 一个文件 `data/board-xxx.md`。**后缀是 `.md`，内容其实是 JSON：**

```json
{
 "title": "大物 · 电磁学",
 "version": 3,
 "viewPinned": false,
 "view": { "s": 0.93, "tx": 70, "ty": 14 },
 "strokes": [ { "tool": "pen", "color": "#1b1d22", "width": 2.6, "points": [106,236,0.5, 201,238,0.5] } ],
 "cards":   [ { "kind": "formula", "x": 100, "y": 190, "w": 320, "h": 100,
                "src": "B = mu0 I / (2 pi r)", "tex": "B = \\frac{\\mu_{0} I}{2 \\pi r}" } ]
}
```

几个刻意的决定：

- **后缀是 `.md`**：现有服务、备份脚本、Git 流程都按 `*.md` 走，改后缀就是改四处；
  而且万一哪天要手改、或者想让别的工具读，"一个开头是 `{` 的 `.md`" 比二进制好救。
  文件名前缀 `board-` 让列表一眼能分开白板和笔记。
- **`points` 是扁平的数字数组**，不是 `[{x,y,p}]`。一个 60 点的笔画，
  对象形式在 JSON 里约 1800 字节，扁平约 400 字节 —— 一节课几百笔，差的是一整个数量级。
  ⚠ 代价是**内存里的形状必须同一个**：解析时一律收敛成扁平数组（见下面坑 #1）。
- **坐标是世界坐标**，缩放平移**不改数据**，只改 `view`。换个缩放再打开，画的东西还在原地。
- **存之前会抽稀**（道格拉斯—普克，容差 0.6 像素）。不抽稀的话，
  Surface 的笔一秒能报 240 个点，一节课的文件能到几兆。
- **`viewPinned` 是个小开关**：`false` = 打开时自动把所有内容装进屏幕；
  `true`（你亲手平移/缩放过）= 老实按存下来的来。为什么需要它 ——
  `tx/ty` 是**相对画布容器**的坐标，容器一变（换摆法、改界面字号、改窗口大小），
  旧坐标就是个错的位置。与其猜"要不要迁移"，不如只在你真的动过之后才记住。

### 白板这块踩过的坑（改之前先看这段）

全是**静默**类型的错：不报错、不崩、状态栏数字看着也对，就是屏幕上不对。

1. **内存里的点必须是扁平数组。** `parseBoardDocument` 一度把点规范化成对象数组，
   而画布按扁平数组读下标 `0/1/2` —— **一笔 10 个点被读成 3 个**，画出来长度是 0，
   屏幕上一片空白；但文件内容、笔数、状态栏全都正常，查了很久都像渲染的问题。
   现在 `normalizeStroke` 一律 `toFlat`，`drawStroke` 走 `toPoints`（两种都认）兜底。
2. **`Array.from(arr, fn)` 会把 `(元素, 下标)` 一起传给 `fn`。** 写序列化的时候
   别图省事把 `round(n, digits)` 直接当 mapFn 传进去 —— 下标会被当成"保留几位小数"。
   包一层箭头函数。
3. **`tx/ty` 和卡片定位必须是同一个基准。** 这一条栽了**三次**：
   canvas 的 `ctx.setTransform` 画在 `.bd-stage` 坐标系里，而一个绝对定位 div 的
   `translate(tx,ty)` 是相对**它自己的包含块**算的。两者一旦不同源，
   卡片就整体偏一个"侧栏宽 + 顶上那一行高"（实测 270 / 46 像素），
   表现是"手写的线和公式卡对不上、内容跑到屏幕外看不见"。
   现在：**任何 `clientX/clientY` 进 `Board.jsx`，第一件事就是减掉容器的 rect**；
   卡片位置也改成用 JS 按同一个公式算 `left/top/width`，不再用 CSS transform 表达视角。
4. **白板那一块必须包一层再放进网格。** `.app` 是 grid，把三列改成两列时，
   只给画布元素指定 `grid-column: 2 / grid-row: 1` 是不够的 ——
   它的兄弟元素（顶上那行文件名）会被**自动放进第 2 行**，
   于是第一行只剩画布、第二行被文件名占掉，看起来就是"白板高度莫名少了一半"。
   规则要写在外层容器（`.bd-shell`）上。
5. **"打开时全部装进屏幕"必须有缩放下限。** 实测在 758×426 的窗口里会算出 0.37 倍，
   公式小到看不清。现在有 `READABLE_FIT_S = 0.55`：
   宁可让你平移着看，也不能把板缩成蚂蚁。
6. **改完模块，页面不一定是新的。** 开发服务器（vite）的 HMR 只换它认得的那一块；
   改的是被 `import` 的数据模块时父模块未必重建 —— 你会看到"明明改了代码，页面还是老样子"。
   实测被骗过一次：样板从 4 张卡加到 5 张，页面一直是 4 张。
   `node scripts/cdp-reload.js` 强制重新导航。
   **另外：5177 端口跑的是 `dist/`（构建产物），不是源码** —— 改完必须 `npm run build`。
7. **`setPointerCapture` 要设在"收到事件的那个元素自己"身上。**
   写字板第一版把捕获设在了外层的 `.wp-padwrap` 上，而监听器挂在 canvas 上 ——
   于是 `pointermove` / `pointerup` 全被重定向到那个 div，
   结果是"笔迹画出来了（实时重画生效），但一笔都没记下来"：
   界面永远停在「还没有笔迹」，点识别只会弹一句"先写一个公式"，
   而且**一个报错都没有**。表现和"画布坏了"一模一样，特别容易查错方向。
8. **别用 `fetch` 连本机 HTTPS。** 实测 node 内置 fetch（undici 实现）连本机 HTTPS
   **会挂住不返回**，而同一个地址用 `tls.connect` / `https.request` 一秒就通。
   所以这个项目所有出网请求都走 `src/lib/http.js`（用 `node:http/https` 手写），
   multipart 也是自己拼的（`src/lib/multipart.js`）。
   `scripts/diag-net.js` 把这条结论钉住了 —— 谁想把 `http.js` 换回 fetch，先跑它。

## 荧光笔为什么是"一条路径一次描"

看 `src/lib/ink.js` 会发现荧光笔和笔走**完全不同的两条路**。这不是随手写的：

| | 笔 | 荧光笔 |
| --- | --- | --- |
| 画法 | 逐段 `beginPath + stroke` | **一条路径，一次 `stroke`** |
| 线宽 | 逐点跟压力变 | 恒定（`HL_WIDTH`） |
| 颜色 | 可选（黑/红/蓝/绿/紫） | 固定荧光黄 |
| 透明度 | 1（不透明） | 0.34（叠在字上） |

原因是**两件事叠加**让记号深浅斑驳（看起来像"笔刷质量差"，其实是画法问题）：

1. **半透明 + 逐段描 + 圆头**：段与段在圆头处重叠，透明色叠两次就变深。
   实测一道弯折的记号：逐段描的深浅标准差 **9.3**，一条路径描的是 **0.3**
   —— 31 倍的差别，肉眼一眼能看出来。`npm run check:highlighter` 量的就是这个。
2. **荧光笔也跟压力改线宽**：马克笔是一道**宽度恒定**的带子，
   一下粗一下细就是 bug。修在**存储层归一化**里（`normalizeStroke`），
   所以**老文件里画过的荧光笔下次打开会自动修好**，不用你重描一遍。

还有一条相关的：荧光笔的颜色和宽度都**钉死，不给你选**。
它的语义是"在已有的字上叠一层记号"，不是"用另一种颜色写字" ——
红色荧光笔盖在黑字上，字就读不清了。
（`check-board.js` 的 `[2b]` 钉着存储层这条，`check-highlighter.js` 钉着像素级的均匀度。）

## 笔记（第二个界面）

把一节课整理成 **量 → 公式 → 关系** 的树，公式输入不用背 LaTeX。
下面这一套是笔记界面的规则。

### 文件格式

一个 `.md` 文件 = 一节课 / 一周的总结。全都是纯文本，用记事本改都行。

```markdown
# 大物 · 电磁学（稳态磁场）

## 一、场怎么算出来

- 安培环路定理
  - 公式 | $\oint_L \vec{B}\cdot d\vec{l} = \mu_0 I_{\text{内}}$
  - 说的是 | 稳恒磁场中，B 沿闭合回路的积分只跟穿过的电流有关
  - 用到的量 | [[B]] [[mu0]] [[I]]
  - 题型 | 求无限长直导线、螺线管、螺绕环的磁场
  - 易错 | 只对稳恒电流成立

## 四、量

- [[B]] | 磁感应强度，T。矢量，描述磁场对运动电荷的作用能力
- [[mu0]] | 真空磁导率，$4\pi\times10^{-7}$ N/A²
```

三条规则：

1. **每行一个节点**，`- ` 开头。缩进 2 个空格 = 下一层。
2. 第一个 ` | ` 后面是正文。正文里的 `$...$` 渲染成公式。
3. **`[[名字]]` 是你亲手连的线。** 打 `[[` 会弹出补全，选一个就行。

`## 标题` 和 `- 项` 可以混着写，工具会自动把 `- 项` 挂到前面那个 `## 标题` 底下。

> **不想记格式：** 打开 `data/zz · 模板（复制这个来写新的一课）.md`，照着【】填空就行。
> 界面里的 **公式条 → `写法`** 页签也有同一份速查，不用离开页面。
> 文件名故意以 `zz` 开头：应用打开时载入列表里**第一个**文件，模板不能抢这个位置。

### 字段名：只认这几个

`公式` `定义` `说的是` `用到的量` `用到了` `题型` `方法` `易错` `注意` `什么时候能用`

定义在 `src/lib/parse.js` 的 `FIELD_KEYS`。想加词就往那个数组里加一个，两边一起生效
（着色层已经从那里 import，不再各留一份）。

**这不是"随便加"——写错的字段名不会报错，它会静默变成一个新节点挂在这一行下面**
（看起来像"内容掉下去了"）。要临时用别的词，就老老实实写成下一层小节点：
`- 什么时候能用 | 只对稳恒电流成立`。

## 连线是怎么算的

引用次数**只统计这两处**：

- `用到的量 | [[B]]` 这种字段行里的 `[[...]]`
- 正文里指向"量"那一支（标题含「量」的那一节）的 `[[...]]`

正文里其他地方写 `[[B]]` 只是**跳转**，不计入次数。这样你行文时可以随手加链接，不会把统计搞乱。

于是：

- **枢纽** = 被引最多的量（左边栏和色标里颜色越亮越是枢纽）
- **孤岛** = 一个公式都没用到的量。孤岛不一定是错的——可能是你还没想到它和谁有关。**这正是值得停一下的地方。**

---

## 编辑区：直接改，但看到的是渲染后的样子

以前是「上面原文、下面预览」两块——你得在下面看效果、在上面找地方改,两边对不上,而且阅读时被压成一小块。现在改成**两个整屏视图**:

顶栏的 **`编辑` / `阅读`** 切换:

- **编辑**:直接改原文,但看到的是渲染后的样子——公式橙色底纹、`[[引用]]` 蓝色胶囊、
  标题变粗变大、字段行整行带色。光标点进去就能改。
- **阅读**:整屏只读,渲染好的树,想怎么翻怎么翻。**点任一节点直接切回编辑并跳到那一行。**

编辑视图里还有两个贴心的:

- **光标所在那一行会亮起来**,其余不动——你随时知道自己在改哪里。
- **那一行上方浮出一个只属于这行的小气泡**,把行内公式用 KaTeX 渲染出来。

底下的状态栏显示「第 42 / 52 行 · 3 级标题 · 字段「公式」」。

顶栏还有个 **`专注`**:只亮着光标那一行,其余压暗,适合一晚上闷头整理。

> **为什么不做成 OneNote 那种彻底的所见即所得?**
> 那样就没法保证"你看到的就是文件里的内容",而且公式编辑会变得很别扭。
> 现在这个做法:字形是渲染的,内容永远是纯文本。
> 代价是「着色层」和「真正的编辑框」必须逐像素对齐,而且**折行位置必须完全一致**——
> `npm run check:align`(静态)和 `npm run check:browser`(真浏览器逐行比坐标)一直盯着这件事。

### 五个踩过的坑（改样式前先看这段）

都是"看起来能跑、实际错位"的类型,所以都写了检查盯着:

1. **行高不能用 px。** 实测:textarea 里写 `line-height: 37.75px`,字号 25.96px 的标题行盒
   **仍然只有 37.75px**——大字被压扁,和光标错位。改成无单位 `1.95` 后,
   行盒 = 字号 × 1.95,标题行自动变高。所以 `--src-lh` 是**无单位倍数**,不是 px。
2. **`.hl-line` 不能用固定 `height`。** 长公式行本来就该折行(示例里第 5 行文本宽 901px >
   可用 793px)。锁死高度的话,折下来的那截会溢出到下一行,**两行叠字**。用 `min-height`。
3. **`.hl-line` 必须用 `content-box` + 负 margin。** 用 `border-box + padding` 会吃掉
   6px 文字宽度,两层折行点就不一致了。
4. **标题行的光标得自己画。** 一个 textarea 只有一个字号,浏览器画的原生光标也只按这个
   字号算几何。实测(`scripts/caret-shot.js`):

   | 层级 | 字号 | 原生光标高 | 原生光标顶(相对内容盒) | 字形顶 |
   | --- | --- | --- | --- | --- |
   | 正文 | 19.375px | 23px | 8px | 8px ✓ |
   | lv1 标题 | 29.06px | 34px | 2px | **11px ✗ 差 9px** |

   所以标题行把原生光标藏掉(`.srcbox.custom-caret .raw { caret-color: transparent }`),
   改用一个按**该行自己的字号**算高度、纵向居中在行盒里的自绘竖条。
   正文行仍然用原生光标(它本来就是对的)。
5. **行底色不能用 `background-color`。** 折行的行,第二行及以后的文字会落到色块外面
   (色块高度只按第一视觉行算),看起来就是"字跑出色块"、和下一行的色块挤在一起。
   必须用 `repeating-linear-gradient` 按 `--src-lh` 重复铺
   (见 `.hl-line.active` / `.hl-line.field.*`)。

> 顺便记一个教训:**类名不要复用。** 工具条的展开箭头一度也叫 `.caret`,和自绘光标
> 撞了名。`npm run check:align` 现在会盯着这件事。

> 还有两个"自检自己骗自己"的坑，都修了，改自检的时候别再犯:
>
> - **`check:mount` 曾用 `readdirSync(data)[0]` 取样本。** Windows 的 `readdir`
>   不保证顺序，`data/` 里多一个 `.md`（那份填空模板）就被选成样本——
>   于是"加载的是 B，却假装自己是 A"，后面所有断言都在拿错内容比对，
>   **报出来的错全是假的**（一次假报 4 条）。现在按内容里的标记显式挑样本，
>   挑不到就立刻退出。
> - **预览曾静默丢掉认不出的正文。** `- 关系名 | 说明` 这种两边都不是字段名的写法，
>   `|` 后面那半句一个字都不显示，看起来像"格式没生效"。
>   现在认不出来就当普通说明渲染——**宁可丑，不可丢**。

## 公式怎么打

顶部常驻公式条，点了就插到光标处，**不用打 `$`**（两端自动补）。

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl` + `/` | 分式，光标自动进分子，`Tab` 跳到分母 |
| `Ctrl` + `2` | 上标 |
| `Ctrl` + `_` | 下标 |
| `Ctrl` + `Shift` + `R` | 根号 |
| `Ctrl` + `Shift` + `V` | 向量箭头 |
| `Ctrl` + `Shift` + `+` / `-` | 整体放大 / 缩小字号 |
| `Tab` | 跳到下一个空位；没有空位就缩进整行 |
| `Shift` + `Tab` | 反缩进 |
| `Enter` | 自动续 `- `，保持缩进 |
| `Ctrl` + `S` | 保存 |
| `[[` | 触发引用补全，`↑↓` 选，`Enter` 确认 |

**选中文字再点工具条按钮 = 把它包进公式里。** 比如选中 `mu0` 再点 `√`，直接变成 `$\sqrt{mu0}$`。

公式渲染用 KaTeX，数学模式里写中文要包 `\text{}`：`I_{\text{内}}`。

## 自检

```bash
# 笔记界面
npm run check         # 解析器：树结构、连线、悬空引用
npm run check:keys    # 键盘：插入位置、Tab 空位跳转
npm run check:scale   # 字号：确认没有写死 px 的字号，并列出各档尺寸
npm run check:align   # 对齐：两层的排版参数必须一致（改了编辑区样式就跑这个）
npm run check:highlight # 着色：公式/引用/标题/字段识别 + HTML 转义
npm run check:render  # 渲染：KaTeX、引用状态、色标
npm run check:mount   # 真挂载：jsdom 里跑"打开 → 编辑 → 阅读 → 保存"，并检查 React 零告警
npm run check:browser # 真浏览器：逐行比对着色层和编辑框的坐标（需先 npm start）

# 白板
npm run check:board          # 纯逻辑：坐标/抽稀/关系推理/存取往返/公式转化（126 项）
npm run check:board-browser  # 真浏览器：画得出来、存得对、两层坐标对齐、三种摆法
npm run diag:board           # 白板"看着不对"时先跑它：把每一层的尺寸和变换都打出来

# 手写识别
npm run check:ocr            # 纯 node：配置/密钥不外泄/multipart 二进制/两家 provider 的契约（99 项，离线）
npm run check:ocr-browser    # 端到端：假识别服务 + 真浏览器，画→识别→变卡片（离线、不花额度）
npm run diag:net             # 出网体检：TLS 握手、识别服务可达性（"发不出去"时先跑它）

# 界面
npm run check:zoom           # 字号：放大/缩小/复位/上下限 + 左栏那个入口也是双向的
npm run check:highlighter    # 荧光笔：在真 canvas 上量一道记号的深浅是否均匀
npm run check:loaded         # 打开的页面是哪个版本、工具条上有什么、笔能不能画

npm run check:all     # 上面所有纯 node 的自检（含 check:board、check:ocr）
npm run perf          # 性能：一次按键要重算多少东西，够不够 60fps
```

**改了编辑区的样式，一定要跑 `npm run check:align`（静态）和 `npm run check:browser`（真浏览器）。**
着色层和编辑框只要有一项排版参数不一致，字和光标就会错位、或者折行位置不同导致叠字。

**改了白板的任何东西，一定要跑 `npm run check:board` 和 `npm run check:board-browser`。**
白板的 bug 几乎都是静默的（不报错、数字看着对、就是屏幕上不对），
只有这两条能挡住。`scripts/check-board.js` 里那些注释写的就是踩过的每一个坑。

**改了手写识别，跑 `npm run check:ocr`（快、离线）和 `npm run check:ocr-browser`（慢、但真的画一遍）。**
后者会起一个假的识别服务，所以**不需要真密钥、不联网、不花额度**，
而且它会检查"我们到底发出去了什么"（是不是 PNG、鉴权头对不对、地址对不对）。
