# 框选追问：答案浮在页边、每次两张图、多轮不带状态

**状态**：已定（2026-09-22）

> ★ **后续（同一天）：候选 2 落地了 —— 见 ADR-0006。**
> 窗里现在有「**⬇ 留到板上**」（每一条回答下面一颗），连它当时列的三条待办一起做了：
> 卡片上的 `ask` 字段、过 `board.js` 那道"只在非默认时才写"的闸、落卡之后小窗的去留。
> ⚠ 本文的**每一条决定都仍然成立** —— 决定 ① 那句话现在读作
> "**你不点那颗按钮**，答案就浮在页边、关掉就散"（原来是"结构上写不了"）。
> 下面「被否掉的替代方案」第 2 条留着原样，那是当时的判断。

用户 2026-09-22 的原话：

> 现在的痛点在于即使有讲解仍然有没理解的地方，而现在的好处在于 pdf/ppt 已经上传，
> ai 知道，加一个可以在页边快速追问这页里面哪个地方是为什么，
> **或者说更加智能一点直接用框选，框中的地方是有疑问的地方并且可以询问这是为什么**。

「课件整理」是一页讲一遍（老师讲他的）；这一条是**你指哪儿他讲哪儿** ——
学生真正卡住的地方常常是某一个符号、某一步变形、某一张图的某个轴，
而那一块在整理出来的讲解里可能一个字都没提到。这条 ADR 定的是四个决定，
前三个是用户当场选的，第四个是实现的形状。

## 决定

**① 答案浮在页边，不动板上的东西。**
`AskBox.jsx` **拿不到 board**（没有 `onCommit` 这种东西），它只发请求、只显示。
关掉小窗，这一轮问答就散了 —— 一个字都不进 `board-*.md`。
理由：卡片的代价不只是"多一张卡"，而是它要摆版、要量尺寸、要能被框选/撤销/导出、
要和关系推断打交道。而"我没懂这一点"是一个**过程**，不是板上的一件东西。
`check:followup-browser` 里专门有一条盯它：**追问全程板文件一个字节都不变**。

**② 能接着追问，每一问都带着前面几轮。**
真正的痛点就是"听了一遍还是不懂"，而那时候人往往已经知道该问什么了
（"那这一步为什么成立？"）。所以一轮小窗里可以问第二句，`turns` 活在组件里。

**③ 每次调用发两张图**（这一条是这一族的骨架）：

| | 是什么 | 给它什么 |
| --- | --- | --- |
| 第一张 | 这一页的**整页**，你圈的那一块上画着**红框** | 上下文（这一步为什么成立，答案常常在上一段） |
| 第二张 | 红框里那一块的**放大图** | 细节（整页缩到 1440 宽之后，那一小块可能只有几十像素） |

红框**画在像素上**，不是"用文字告诉它坐标"—— 视觉模型对坐标无感、对红框有感。
两张图的顺序写在提示词里（不说清它会对着裁图讲整页）。

**④ 服务端不留会话状态：每一问自带全部上下文。**
`/api/ocr` 的 `mode:'ask'` 每次收「两张图 + 页码 + 这一问 + 前面几轮」，
拼成 `[user: 图 + 说明 + 这一问] + [上一轮的 user/assistant…]`。
代价如实写下来：**"接着问"要重新付一次图片的钱**（那两张图重发一遍）。
换来的是**没有状态可错**：换页、换板、关窗口，都不会在服务端留下一个指向别处的会话，
也就不存在"这次问的是第 3 页、它还记得上一次那页"这种事。

## 被否掉的替代方案

1. **答案直接落成板上的一张卡，贴在框旁边**（用户第一个否掉的）：
   读起来很顺（"你框中的那块和『为什么』永远在一起，重开还在"），
   但用户要的是**页边快速追问** —— 一次课下来会问十几处，板上就被问答卡淹了，
   而白板是画关系的地方。
2. **先浮在页边，窗里有一颗「贴到板上」再落卡**：多一步操作，
   而板上只有他认可的那些。**留着当以后的加法** —— 真要落卡，
   那时才需要给卡片加" anchoring"字段（`askPage` + 页内归一化矩形），
   而且必须过一次 `board.js` 的"只在非默认时才写"那一道闸。现在不做。
3. **只发裁图 / 只发整页**：前者最便宜，但模型不知道这是哪一页的什么
   （「为什么」最需要上下文），答案质量掉一截；后者在小字、下标、符号上直接看不清。
4. **给这一趟单独一个模型档（像 `boardModel` 那样）**：多一个配置字段、多一处
   "设置里改了不生效"的可能。先用普通那档 —— 它一次只讲一个点，
   不是"读一整页"，价钱上更该走便宜那档。
5. **把 `question` / `history` 也塞进 `/api/structure` 那个口**：
   那个口的契约是"一段纯文本 → 一个 JSON 骨架"，和这条链路没有一处相同。

## 后果

- 「？问这里」有两个入口：**选区浮层上那颗**（框住之后浮出来，主人流），
  和**工具条上那颗**（"这个功能在哪"的答案）。两颗都走 `Board.jsx` 的同一个 `openAsk`。
  ★ 工具条那颗**不做成灰的**（和「✨ 美化手写」同一条理由）：
  可点 + 当场说清下一步，比一颗点不动的灰按钮省事。
- **"这一块在第几页"是几何算出来的**（`ask-region.js` 的纯函数），不让用户选页号：
  他圈的就是他看不懂的地方，再让他说一遍"这是第 7 页"是多余的动作，而且会说错。
- 服务端多了两个字段（`question` / `history`）和一个 `mode`，`/api/ocr` 从
  "一张图 → 一段字"变成"两张图 + 一段对话 → 一段回答"。
  `extractTextPart` 那一族**读不了二进制**，所以 `multipart.js` 多了一个按名字取文件的
  `extractFilePartNamed`（第二张图叫 `file2`）。
- 温度从 0 改成 **0.3**（只有这一趟）：识别是"抄"，而它是"讲明白"——
  0 会让回答变成教科书腔，那正是用户抱怨"读完还是不懂"的原因之一。
- 提示词里**没有**任何位置/尺寸字段，答案落在哪儿是本地算的
  （和「课件整理」同一条纪律：模型只交内容）。
- **和「课件整理」的关系改了一条**（2026-09-22，用户对着整理出来的卡片说的）：
  「这些解说的卡片生成后默认状态应该是定住的，用户要移动再解开」。
  所以 `placeDeckCards` 造出来的卡片**一律带 `locked: true`**（讲解 / 重点 / 公式一视同仁）——
  这一条 ADR 的理由在这儿正好接上：整理完是**照着课件往下读**，
  而这一族（整理 + 追问）解决的都是"手在屏幕上、眼睛在课件上"这件事，
  卡片被手蹭走的代价比"想挪时多点一下 📌"大得多。
  ⚠ 它不改变本文的任何决定（追问的答案仍然浮在页边、**默认**不落卡 ——
  落卡要你自己按「⬇ 留到板上」，见 ADR-0006）——
  只是"贴上来的素材"和"我自己的手写"从此在默认状态上分开了。
