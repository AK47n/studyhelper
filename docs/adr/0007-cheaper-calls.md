# 出网这一趟的账：按缓存形状拼消息、把用量读出来、给 max_tokens 兜底

**状态**：已定（2026-09-22）

## 背景：用户要的是"省钱省时间"

用户原话只有一句：**「优化学习流程」**。追问他指的是哪一段，他选的是
「**省钱省时间**：49 页一页一次调用、追问每轮重发两张图」。

按这个仓库的规矩（**先量再改**），动手之前先花了几次真实调用把账量出来。
量出来的东西**推翻了"49 次调用"和"重发两张图"这两个直觉** —— 它们都不是主因。

## 量到的（一手文档 + 真实调用）

### ① 钱几乎全在 thinking 上

`deepseek-flash` **默认开着 thinking，而且默认 effort = high**（官方 Thinking Mode 文档原话：
"Thinking mode is enabled by default, with the default effort being `high`"）。
我们从来没关过它。同一个模型、同一页、同一张图、同一句提示词，实测：

| | 第 1 次 | 同内容重发 | 带 `max_tokens=4000` |
| --- | --- | --- | --- |
| 用时 | 0.68 s | 0.45 s | **16.4 s** |
| 输入 | 1979（命中 768） | 1979（命中 1792） | 1979（命中 1792） |
| 输出 | 1327 | 1402 | **3618** |
| 其中 thinking | 916 | 941 | **3219** |
| 正文 | 714 字 | 765 字 | 737 字 |

thinking 占输出的 **69%~89%**（课件整理、追问那几趟都一样），按**输出**计价 ——
而输出是最贵的一档（$0.6~1.2/M），是输入未命中的 2~4 倍、是输入命中的 200 倍。
输入那一侧（含那 1792 个命中 token）**每页只值 $0.00003**，是噪音。

**但这一条这次没动**：用户听完数字之后仍然选「全部保留 high」（2026-09-22 明确重申）。
开关留在原地，账记在这里 —— 想省这一口的话，做法是
`thinking: { type: 'disabled' }`（或 `reasoning_effort: 'low'`），改一处 `callDeepSeek` 的请求体。

### ② `temperature` 今天是**静默失效**的

同一页文档写着：thinking 模式下 `temperature`"不会报错，但也不起作用"。
所以代码里那两处温度（识别 `0`、追问/作业 `0.3`）**一直没有生效过** ——
README 里"0 会让回答变成教科书腔，所以追问用 0.3"那条论证，从来没被验证过。
它们留着（给"哪天关了 thinking / 换了模型"用），但**不许**再把它当成"口吻已经调好了"。

### ③ 上下文缓存默认开，而我们的追问**自己把前缀切断了**

缓存命中 $0.003/M、未命中 $0.15/M —— **差 50 倍**。规则是"必须**完整匹配**一个缓存前缀单元"。
而 `ASK_PROMPT` 的最后一行原来是 `学生的问题是：{{QUESTION}}`，**两张图排在它后面**：
前缀在图片之前就分叉了，于是**每一轮追问那两张图都按未命中重付一遍**。
（顺带一提，"这一问"原本还排在它自己的历史**前面**，语义也是倒的。）

### ④ `max_tokens` 把 thinking 也算在内

`max_tokens=100` 那一次：100 个 token **全被思维链吃掉**，`content` 长度 **0**、
`finish_reason` 是 `length`。所以它**不是省钱开关** —— 设小了会把答案整个掐掉，
而前端只会看到"模型没回内容"→ 重读一遍，既慢又更贵。

### ⑤ "一次发多页"省不到钱，"重发两张图"也不是主因

- 图片按尺寸折算 token、**每张上限 1024**，而且小于 544×544 的图会被**放大**到那个尺寸 ——
  所以本地把图缩一缩、把裁图放大到 900 宽，**都不改变 token 数**；
  打包多页发一次，图片和输出的 token 一个不少，省的只有那份 1580 字的提示词，
  而它本来就命中缓存（49 页合计不到一分钱）—— 却要赔掉"一页一次调用"的三个好处
  （失败隔离、进度、重试粒度）。**不做。**
- 时间的瓶颈是**并发**：单次调用实测 0.45~16.4 秒，49 页串行十几分钟。

## 决定

**① 追问按官方 Example 1 的形状重拼消息。**

```
[0] user   = 两张图 + 那段提示词   ← 每一轮**逐字相同**
[1..n]     = 上一轮那些轮次（… 我问的、它答的）
[n+1] user = **这一次问的那句话**
```

原来"这一次问的"拼在第 0 条（提示词的最后一行）。挪到最后一条之后，
第 2 轮就是第 1 轮**原样接着长**（`A+B` → `A+B+C`），第 1 轮留下的缓存前缀单元被完整匹配。
**真 API 实测**：第 2 轮命中 **87%**（cached 1024 / prompt 1179），
未命中从旧形状的 ~1150 降到 ~155。两条连续的 user 消息上游也照收（实测 `ok: true`）。

★ 顺带修掉"新问题排在它自己的历史之前"这个语义倒置。
★ 断言落在两处：`check-askfollow` 的 C1/C1b（提示词里**不许**有那一问）、
`check-followup-browser`（上游真收到的四条消息 + **两轮第 0 条逐字相同**）。

**② 把 `usage` 读出来，并在界面上显示。**

`server-ocr.js` 的 `usageOf` 一处归一上游那两套字段名，`/api/ocr` 原样透出，
界面上一行小字：`输入 3.9万（命中 90%） · 输出 6.4万（其中思考 5.1万）`。
课件整理那栏显示**累计**（含失败的页 —— 它花了钱），追问显示**每一条回答各自**一份。

★ 这是这次真正的长期收益：**在这之前整个仓库一次都没读过 `usage`**，
于是"改了之后是不是更省了"只能靠感觉。尺子先立起来，后面才谈得上优化。
★ 纪律：**"读不到"不许变成"是 0"** —— 上游没给就是 `null`，界面那一行宁可不出现。

**③ 每一趟一个 `max_tokens`（`MODE_LIMITS`），只当跑飞兜底。**

不设的话上限是 384K token，一次调用最贵能到 $0.46。值按实测留三四倍余量
（同一页 thinking 900~3200 + 正文 500~800 → 一页给 8000）。
**注释里写明了它把 thinking 也算在内** —— 不然下一个人一定会拿它当省钱开关用。

**④ 并发做成设置里的旋钮，默认 3 → 6。**

`docConcurrency`（`DEFAULT_CONFIG` + `CONFIG_KEYS` + `normalizeConfig` 夹 1~12），
经 `/api/ocr/status` 发给浏览器，`readDeck` 用它。
官方并发上限是 2500，6 路连零头都不到。代价如实写在设置面板里：
**「■ 停止」拦不住已经发出去的请求**，路数越多，按下停止那一刻已经花掉的钱越多。

**⑤ thinking 保持默认 high 不动。**

用户 2026-09-22 在看过上面那张表之后仍然这么定。这一条是**有意的选择**，不是漏掉。

## 被否掉的替代方案

1. **把 thinking 关掉 / 降到 low**：钱的 69%~89%、时间的 0.68s vs 16.4s 都在那儿 ——
   是最大的一口。用户明确要保留（"先想一想"本身有价值，尤其「作业辅导」是真在做题）。
   开关留着，账记在 ADR 与 README 那一节。
2. **一次发多页（`buildBatches` 那个半成品）**：见量到的 ⑤。
   `buildBatches` 继续留在 `doc-cards.js` 里当纯函数（有断言），但**不使用**。
3. **用 `max_tokens` 压 thinking**：见量到的 ④ —— 它会把答案一起掐掉。
4. **把图渲染小一点省钱**：见量到的 ⑤，图片 token 有上限、小图还会被放大，省不到。
5. **服务端记会话、由服务端复用上下文**：ADR-0005 决定 ④ 那条"没有状态可错"是这一族的底，
   不动。缓存命中是**上游**替我们做到的，不需要我们持有状态。

## 后果

- `ASK_PROMPT` 不再有 `{{QUESTION}}`；新增 `askQuestion()`（那一问单独成一条消息）。
  任何"把问题拼回提示词"的改法都会**悄悄**把缓存命中弄丢 —— 断言钉着。
- 请求体多一个 `max_tokens`；回包多一个 `usage`（读不出来是 `null`）。
- 配置多一个 `docConcurrency`；`/api/ocr/status` 多报一个它。
- 新文件 `src/lib/usage.js`（纯函数，`check-doc-read` 的 [8] 钉着）。
- 界面多两行小字（课件整理那栏一行、追问每条回答下面一行）。
- **重新量过的成本基线（49 页、off-peak）**：约 $0.05，其中 80% 以上是输出、约一半是 thinking。
  这个数以后要跟着价格表和模型版本一起复量 ——
  README 那一节记着怎么量（探针的形状写在 `.cache/` 里用过就删）。
