# studyhelper · 过手总结台

把一节课整理成 **量 → 公式 → 关系** 的树，公式输入不用背 LaTeX。

不联网、不上传、不替你总结。数据就是你硬盘上的纯文本文件。

---

## 怎么跑

双击 **`启动 studyhelper.bat`**。浏览器会自动打开 http://127.0.0.1:5177/

关掉那个黑窗口就是关掉它。数据在 `data/` 目录里。

> 想改代码看实时刷新：在一个终端跑 `npm run dev`（前端热更新在 5180 端口），
> 另一个终端跑 `npm start`（后端在 5177）。改完 `npm run build` 一次，之后还是双击 bat。

---

## 文件格式

一个 `.md` 文件 = 一节课 / 一周的总结。全都是纯文本，用记事本改都行。

```markdown
# 大物 · 电磁学（稳态磁场）

## 一、场怎么算出来

- 安培环路定理
  - 公式 | $\oint_L \vec{B}\cdot d\vec{l} = \mu_0 I_{\text{内}}$
  - 说的是 | 稳恒磁场中，B 沿闭合回路的积分只跟穿过的电流有关
  - 用到的量 | [[B]] [[mu0]] [[I]]
  - 题型 | 求无限长直导线、螺线管、螺绕环的磁场
  - 易错 | 只对稳恒电流成立

## 四、量

- [[B]] | 磁感应强度，T。矢量，描述磁场对运动电荷的作用能力
- [[mu0]] | 真空磁导率，$4\pi\times10^{-7}$ N/A²
```

三条规则：

1. **每行一个节点**，`- ` 开头。缩进 2 个空格 = 下一层。
2. 第一个 ` | ` 后面是正文。正文里的 `$...$` 渲染成公式。
3. **`[[名字]]` 是你亲手连的线。** 打 `[[` 会弹出补全，选一个就行。

`## 标题` 和 `- 项` 可以混着写，工具会自动把 `- 项` 挂到前面那个 `## 标题` 底下。

> **不想记格式：** 打开 `data/zz · 模板（复制这个来写新的一课）.md`，照着【】填空就行。
> 界面里的 **公式条 → `写法`** 页签也有同一份速查，不用离开页面。
> 文件名故意以 `zz` 开头：应用打开时载入列表里**第一个**文件，模板不能抢这个位置。

### 字段名：只认这几个

`公式` `定义` `说的是` `用到的量` `用到了` `题型` `方法` `易错` `注意` `什么时候能用`

定义在 `src/lib/parse.js` 的 `FIELD_KEYS`。想加词就往那个数组里加一个，两边一起生效
（着色层已经从那里 import，不再各留一份）。

**这不是"随便加"——写错的字段名不会报错，它会静默变成一个新节点挂在这一行下面**
（看起来像"内容掉下去了"）。要临时用别的词，就老老实实写成下一层小节点：
`- 什么时候能用 | 只对稳恒电流成立`。

## 连线是怎么算的

引用次数**只统计这两处**：

- `用到的量 | [[B]]` 这种字段行里的 `[[...]]`
- 正文里指向"量"那一支（标题含「量」的那一节）的 `[[...]]`

正文里其他地方写 `[[B]]` 只是**跳转**，不计入次数。这样你行文时可以随手加链接，不会把统计搞乱。

于是：

- **枢纽** = 被引最多的量（左边栏和色标里颜色越亮越是枢纽）
- **孤岛** = 一个公式都没用到的量。孤岛不一定是错的——可能是你还没想到它和谁有关。**这正是值得停一下的地方。**

## 编辑区：直接改，但看到的是渲染后的样子

以前是「上面原文、下面预览」两块——你得在下面看效果、在上面找地方改,两边对不上,而且阅读时被压成一小块。现在改成**两个整屏视图**:

顶栏的 **`编辑` / `阅读`** 切换:

- **编辑**:直接改原文,但看到的是渲染后的样子——公式橙色底纹、`[[引用]]` 蓝色胶囊、
  标题变粗变大、字段行整行带色。光标点进去就能改。
- **阅读**:整屏只读,渲染好的树,想怎么翻怎么翻。**点任一节点直接切回编辑并跳到那一行。**

编辑视图里还有两个贴心的:

- **光标所在那一行会亮起来**,其余不动——你随时知道自己在改哪里。
- **那一行上方浮出一个只属于这行的小气泡**,把行内公式用 KaTeX 渲染出来。

底下的状态栏显示「第 42 / 52 行 · 3 级标题 · 字段「公式」」。

顶栏还有个 **`专注`**:只亮着光标那一行,其余压暗,适合一晚上闷头整理。

> **为什么不做成 OneNote 那种彻底的所见即所得?**
> 那样就没法保证"你看到的就是文件里的内容",而且公式编辑会变得很别扭。
> 现在这个做法:字形是渲染的,内容永远是纯文本。
> 代价是「着色层」和「真正的编辑框」必须逐像素对齐,而且**折行位置必须完全一致**——
> `npm run check:align`(静态)和 `npm run check:browser`(真浏览器逐行比坐标)一直盯着这件事。

### 五个踩过的坑（改样式前先看这段）

都是"看起来能跑、实际错位"的类型,所以都写了检查盯着:

1. **行高不能用 px。** 实测:textarea 里写 `line-height: 37.75px`,字号 25.96px 的标题行盒
   **仍然只有 37.75px**——大字被压扁,和光标错位。改成无单位 `1.95` 后,
   行盒 = 字号 × 1.95,标题行自动变高。所以 `--src-lh` 是**无单位倍数**,不是 px。
2. **`.hl-line` 不能用固定 `height`。** 长公式行本来就该折行(示例里第 5 行文本宽 901px >
   可用 793px)。锁死高度的话,折下来的那截会溢出到下一行,**两行叠字**。用 `min-height`。
3. **`.hl-line` 必须用 `content-box` + 负 margin。** 用 `border-box + padding` 会吃掉
   6px 文字宽度,两层折行点就不一致了。
4. **标题行的光标得自己画。** 一个 textarea 只有一个字号,浏览器画的原生光标也只按这个
   字号算几何。实测(`scripts/caret-shot.js`):

   | 层级 | 字号 | 原生光标高 | 原生光标顶(相对内容盒) | 字形顶 |
   | --- | --- | --- | --- | --- |
   | 正文 | 19.375px | 23px | 8px | 8px ✓ |
   | lv1 标题 | 29.06px | 34px | 2px | **11px ✗ 差 9px** |

   所以标题行把原生光标藏掉(`.srcbox.custom-caret .raw { caret-color: transparent }`),
   改用一个按**该行自己的字号**算高度、纵向居中在行盒里的自绘竖条。
   正文行仍然用原生光标(它本来就是对的)。
5. **行底色不能用 `background-color`。** 折行的行,第二行及以后的文字会落到色块外面
   (色块高度只按第一视觉行算),看起来就是"字跑出色块"、和下一行的色块挤在一起。
   必须用 `repeating-linear-gradient` 按 `--src-lh` 重复铺
   (见 `.hl-line.active` / `.hl-line.field.*`)。

> 顺便记一个教训:**类名不要复用。** 工具条的展开箭头一度也叫 `.caret`,和自绘光标
> 撞了名。`npm run check:align` 现在会盯着这件事。

> 还有两个"自检自己骗自己"的坑，都修了，改自检的时候别再犯:
>
> - **`check:mount` 曾用 `readdirSync(data)[0]` 取样本。** Windows 的 `readdir`
>   不保证顺序，`data/` 里多一个 `.md`（那份填空模板）就被选成样本——
>   于是"加载的是 B，却假装自己是 A"，后面所有断言都在拿错内容比对，
>   **报出来的错全是假的**（一次假报 4 条）。现在按内容里的标记显式挑样本，
>   挑不到就立刻退出。
> - **预览曾静默丢掉认不出的正文。** `- 关系名 | 说明` 这种两边都不是字段名的写法，
>   `|` 后面那半句一个字都不显示，看起来像"格式没生效"。
>   现在认不出来就当普通说明渲染——**宁可丑，不可丢**。

## 字号

**觉得字小,右上角点 `A+`。** 或者按 `Ctrl` + `Shift` + `+` / `-`。左栏底部也有一个入口。

调整范围 90% – 200%,默认 **125%**(正文 20px)。调完会记住,下次打开还是这个大小。
想回到默认:点一下那个百分比数字。

整个界面的字号由一个 CSS 变量 `--s` 驱动(`src/styles.css` 顶部),侧栏宽度也跟着长,
所以放大后文字不会被挤掉。想直接改默认值就改 `--s: 1.25` 这个数。

## 公式怎么打

顶部常驻公式条，点了就插到光标处，**不用打 `$`**（两端自动补）。

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl` + `/` | 分式，光标自动进分子，`Tab` 跳到分母 |
| `Ctrl` + `2` | 上标 |
| `Ctrl` + `_` | 下标 |
| `Ctrl` + `Shift` + `R` | 根号 |
| `Ctrl` + `Shift` + `V` | 向量箭头 |
| `Ctrl` + `Shift` + `+` / `-` | 整体放大 / 缩小字号 |
| `Tab` | 跳到下一个空位；没有空位就缩进整行 |
| `Shift` + `Tab` | 反缩进 |
| `Enter` | 自动续 `- `，保持缩进 |
| `Ctrl` + `S` | 保存 |
| `[[` | 触发引用补全，`↑↓` 选，`Enter` 确认 |

**选中文字再点工具条按钮 = 把它包进公式里。** 比如选中 `mu0` 再点 `√`，直接变成 `$\sqrt{mu0}$`。

公式渲染用 KaTeX，数学模式里写中文要包 `\text{}`：`I_{\text{内}}`。

## 数据 / 备份

- 数据目录：`data/`，一个总结一个 `.md` 文件。
- 服务是**原子写**的（先写临时文件再改名），写一半断电不会留下坏文件。
- 你可以用 VSCode 直接改 `data/` 里的文件；页面检测到磁盘变了会提示你点「重载」。

### 备份到 GitHub

仓库：**https://github.com/AK47n/studyhelper**（私有）。`data/` 里的笔记也在版本控制里，
所以换电脑、误删、改坏了，都能从 GitHub 找回来。

写完之后**双击根目录的 `备份到GitHub.bat`**（或者 `npm run sync`）。它会：
提交 → 拉取（`--rebase`，避免两台机器写出分叉）→ 推送，任何一步失败都会说清楚卡在哪。

```
  studyhelper 备份到 GitHub
  ─────────────────────────────────────
  https://github.com/AK47n/studyhelper.git
  改动清单：
   M data/示例 · 大物电磁学.md
  ✓ 已提交
  ✓ 已同步远端
  ✓ 已推送到 GitHub
```

换台电脑继续写：`git clone` 下来，`npm install`，`npm run build`，然后照旧双击启动。

> 已知的小摩擦：这个 .bat 是双击用的，所以**它不会自动跑**。想省掉这一步，
> 可以让服务在每次保存后自动推一次——没做，是因为那会在后台悄悄动你的 GitHub 账号，
> 得你点头再加。

## 自检

```bash
npm run check         # 解析器：树结构、连线、悬空引用
npm run check:keys    # 键盘：插入位置、Tab 空位跳转
npm run check:scale   # 字号：确认没有写死 px 的字号，并列出各档尺寸
npm run check:align   # 对齐：两层的排版参数必须一致（改了编辑区样式就跑这个）
npm run check:highlight # 着色：公式/引用/标题/字段识别 + HTML 转义
npm run check:render  # 渲染：KaTeX、引用状态、色标
npm run check:mount   # 真挂载：jsdom 里跑"打开 → 编辑 → 阅读 → 保存"，并检查 React 零告警
npm run check:browser # 真浏览器：逐行比对着色层和编辑框的坐标（需先 npm start）
npm run check:all     # 前七项
npm run perf          # 性能：一次按键要重算多少东西，够不够 60fps
```

**改了编辑区的样式,一定要跑 `npm run check:align`(静态)和 `npm run check:browser`(真浏览器)。**
着色层和编辑框只要有一项排版参数不一致,字和光标就会错位、或者折行位置不同导致叠字。

```
  src/

      parse.js         文件格式的全部定义：树、字段、引用、连线

    components/
      FormulaBar.jsx

      ContextPanel.jsx 右侧：被引用于 / 用到了，可点击跳转
  data/                你的总结（纯文本）
    zz · 模板….md      【】填空模板：不用会 Markdown 也能写（文件名以 zz 开头，

```
