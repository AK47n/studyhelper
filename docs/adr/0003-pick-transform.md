# 框住的那一块是一个整体：笔迹分轴、卡片等比、卡片自带 `rot`

**状态**：已定（2026-09-21）

用户 2026-09-21 的原话：**「框选中任意的字迹——卡片都应该能够放大，旋转，这点类似 onenote」**。
在这之前只有**一个规整过的图形**（`stroke.shape`）四周有手柄，普通手写和卡片都没有。
这条 ADR 定的是"框住的那一撮东西怎么动"的四条决定。

## 决定

**① 手柄是「选区」的属性，不是「图形」的属性。**
框住什么就画在什么上：几笔字、一坨乱涂、规整过的图形、以及**落在框里的卡片**
（框选收谁：笔迹碰着就算、卡片**中心**在框里才算 —— 和「留下板框」「复制」同一句话，
`geometry.js` 的 `membersInBox`）。判"框住了什么、框多大"只在 `selection.js` 一处
（`readSelection` / `pickBox`），界面那一半是 `Board.jsx` 的两段手势 + `BoardCanvas.jsx`
的 `PickHandles`。**`stroke.shape` 不再是"有没有手柄"的判据** —— 它现在只决定
"拖动时走参数还是走点"。

**② 笔迹分轴，卡片等比。**
- 笔迹是**点**：`fx`/`fy` 分别乘上去，横着拉就是"字被拉宽了"（和"圆拉成椭圆"同一条）。
  线宽按**几何平均** `√(fx·fy)` 一起缩（放大三倍还是原来那么细，看着像复印件），
  夹在 `PICK_MIN_W ~ PICK_MAX_W`。
- 卡片不行：它的内容是**文字**，`w` 是**硬约束**（写小了当场裁内容，README 第 15 条
  那三个坑量过），字号又只有一个倍率。所以卡片吃**几何平均**，
  而**位置**（可视中心）吃完整的 `fx`/`fy` —— 它待在这个变换让它待的地方，只是自己不跟着变形。
  代价如实写下来：非等比拖的时候，卡片和周围的笔迹会错开一点点。

**③ 卡片的旋转是一个字段 `rot`（弧度，绕它自己的中心），和 `scale` 并列。**
它只在真转过时才写进文件；归一化用**图形那一份** `normAngle`（全仓库只有一份：
转一圈回来精确是 0，不是 `1e-17`、也不是 `-0`）。
卡片**没有"点"**，所以"转过之后重开还在"只能靠这个字段 —— 和 `shape-object.js`
文件头 ③ 是同一个道理（`shapes.js` 烤出来的东西在文件里和普通笔迹长得一模一样，
不给它一个身份，重开就退化成"一堆摆得很正的点"）。

**④ 旋转绕「选区包围盒的中心」。**
不是"各自绕自己的几何中心"：选多个东西（或者一撮字 + 一张卡）时，转轴只能是那个框的中心，
绕其中某一个的中心转，屏幕上就是"框绕着别处甩"。代价：单个三角形在手时，
转轴从"重心"变成"框中心"（**故意的** —— 用户看到的是那个虚线框）。
每一帧都从**按下那一刻的板**重算（不是累加），一次拖动 = 一步撤销。

## 被否掉的替代方案

1. **卡片也分轴**（改 `w`/`h`，或者给卡片加 `sx/sy`，或者套一个 CSS `scale(fx,fy)`）：
   不行。前两条给"这张卡长什么样"造第二份真相（`scale` 那份还在），
   而且必须回答"文字跟不跟着变形"；第三条最坏 —— 变换不进布局，
   于是 `w`/`h`/关系推断/命中测试全都说的是另一个矩形（ADR-0002 那根黑线是同宗）。
2. **把选区整体存成一个变换矩阵**（点不动、矩阵说了算）：
   和"点是唯一真相"、"框线是内容的函数"（ADR-0001）直接冲突 ——
   一存矩阵，落在哪、挨着谁、算多大就都要先乘一遍，而这个仓库为"同一个矩形两处各算一遍"
   已经记了十几条账。
3. **旋转时"把点转一遍"而不存 `rot`**：卡片没有点；而且转过 90° 的矩形
   靠改点回不到**轴对齐**（第 50 条 ②）。形状那条路早就定了用参数，卡片跟着同一条。
4. **只给图形手柄**（即维持原样）：用户明确要的是"任意字迹 + 卡片"。

## 后果

- **`geometry.cardBounds` 变成"可视外接框"**（含倍率和旋转）：关系（包含/重叠/挨着）、
  板框的框线、"装回屏幕"吃的都是它 —— 肉眼看到的范围就是它。
  代价是斜着的卡外接框略微偏大（四角那一圈），这是**已知且接受**的近似。
- **量尺寸必须用布局值**：`sampleCardForFit` 从 `getBoundingClientRect()` 换成
  `offsetWidth/offsetHeight` —— 前者返回的是**变换之后**的外接框，
  拿它去改 `w`/`h` 会让卡片"越转越胖"**而且存进文件**（README 第 52 条 ④）。
  卡片右下角那个缩放柄同理。
- **箭头打的"边点"要转进卡片自己的坐标系里算**（`nodes.js` 的 `edgePointOf` 认 `rot`），
  不然尖会停在离卡片还有一段的空中。`nodeList` 因此给卡片多带一个 `rect`
  （没转的那个可视矩形）。
- **固定（📌）住的卡片框不进来**：框选是按坐标算的，它不问卡片收不收指针事件，
  而 📌 的语义正是"选不中"（README 第 19 条）。漏了这一条，"框一大片按 Delete"
  会把钉住的卡一起删掉。
- **`Delete` 把笔迹和卡片一起删**（`focus.js` 的 `deleteIntent` 报出 `cards`）：
  只删一半的表现是"删除做了一半"。
- **`lastLassoRef` 退休**（"留下板框/复制靠最后一次框选的矩形找卡片"）：
  卡片自己进选区之后那句话有了唯一答案，它连带的那个老 bug
  （"框住 → Esc → Ctrl+C 复制出上一次那张卡"）一起没了。
- **还没做的**（README「还没做的」一节）：卡片不吃非等比、选区不能只动其中一样、
  旋转不吸附、板框自己不会转（框线是成员的轴对外接框，里面有转过的卡就会变大）。
- **性能**（2026-09-21，用户报「大字体旋转时卡顿」之后补的两条）：
  · **"每帧重算但这一帧没人看得见"的东西要挪到安静之后**：形状判读（那颗「◯ 规整」的
    可见性）原来跟着 `sel.strokes` 每帧重跑一遍，实测在用户的板上是 O(框住笔数 × 拟合)
    —— 改成"选区换了立刻算一次 + 板安静 240ms 再算一次"（`SHAPE_SETTLE_MS`）。
    和 `card-fit.js` 的 `board-changed`（板安静 400ms 再量尺寸）是同一条政策。
  · **缩放/旋转中给卡片一个合成器提示**（`.bd.xforming .bd-card { will-change: transform }`，
    松手就撤）：不带提示时卡片的 `transform` 每变一次都要重新光栅化整张卡，
    而大字号公式卡（面积大 + KaTeX 那一坨 span + 14px 模糊阴影）正是最贵的那一种。
    ⚠ 这一条**没能在这个仓库里复现**（headless 里 1400 笔 + 1680×480 的卡旋转也只要 ~2ms/帧），
    是按机理改的；判据因此钉的是**接线**（拖动中 computed `will-change` 必须是 `transform`，
    松手必须回到 `auto`），不是帧率。详见 README 第 53 条。
  · 还没做的一条（真要更狠再走）：**旋转时不提交整块板，直接把角度写在选中卡片的 DOM 上**，
    松手才 commit（像 `syncViewCorrection` 那样"过渡量"）。代价是"屏幕上的位置"和
    "板里的数据"短暂不一致 —— 手柄、`.bd-inkbox` 都得跟着这套过渡量走，得先想清楚。
- **自检**：`check-board` 的 **[6m] ⑫⑬**（纯逻辑：包围盒含可视外框、分轴/几何平均/
  锚点不动/倍率夹住、绕选区中心转、`rot` 的落盘与往返、转一圈回 0）；
  `check:shape` 的 **[12g]**（任意两笔认不出形状的字迹：分开拉 → 旋转 90° → 一次 Ctrl+Z）
  与 **[12h]**（卡片进选区、几何平均、`rot` 落盘 + DOM 上真有 `rotate()`、
  Delete 一起删、钉住的框不进来）。
  ⚠ 这一轮的自检当场抓出一个**两天前就埋下的老 bug**：拖角缩放的分母只在拖 `se` 时是对的
  （另外三颗柄会把倍率算成"指针的像素数"），因为 [12c] 只拖过 `se` —— 账在 README 第 52 条 ①。
